# 직업·스킬·성장 — 첫 데모 검토 초안 v1

> **과거 기준 보존:** 아래 ‘직업 변경 불가/4직업 한계’는 2026-09-13 사용자 요청으로 대체됐다. 최신 성장 설계는 [조합 전직 v3](research-expansion/class-progression-v3.md)다. 이 문서는 당시 구현 차이와 재사용 가능한 기술 후보를 기록한 것이며 현재 전직 금지 정책이 아니다.

작성일: 2026-09-12. 범위: 핀 중심 20~30분 데모와 후속 콘텐츠 준비. **검토용 문서이며 게임 데이터·밸런스·확정 기획을 변경하지 않는다.**

## 1. 확정 기획과 실제 구현의 구분

| 항목 | 기존 기획 | 이번 점검에서 확인한 구현 상태 |
|---|---|---|
| 직업 | 캐릭터와 결합한 4종, 세이브 시작 시 선택, 시작 후 직업 변경 불가 | `characters.json`은 스키마만 있고 실제 파일 없음. 4종 선택 구현 완료로 해석하지 않음 |
| 핀의 계열 | 검술 / 수호 / 기사도, 각각 6단계 × 단계당 2노드 | `skills.json` 없음. 아래 6노드는 새 검토 초안 |
| 고유 반격 | 저스트 가드 후 반격 입력 윈도우로 패리 슬래시 | `player.gd`는 피해 차단·경직 요청·플래시를 구현. 전용 반격 윈도우·공격 배율은 이 경로에 없음 |
| 액티브 슬롯 | 2개 장착 | 입력 액션·HUD 슬롯이 있다는 사실만 확인. 스킬 실행·성장 구현 완료 아님 |
| 성장 | 최대 50레벨, 레벨업당 SP 1·스탯 3 | `stats.json`에 해당 값 존재. `exp_curve.csv` 없음. 전 계수 연결 완료 아님 |
| 퀘스트 SP | 보상으로 추가 획득 | `quest_system.gd`의 `pending_skill_points`에 누적되는 placeholder |

근거: GDD 3~5장, BRD F1-1~F1-4·F2-5, `docs/specs/data_tables.md` 2~5장, `game/scripts/player/player.gd`, `game/scripts/systems/quest_system.gd`, `game/data/stats.json`. 파일 부재는 작성일 현재 확인 결과다.

## 2. 기존 4인 직업 소개 카드

아래 정체성·무기·고유 메커니즘은 기존 GDD/캐릭터 문서의 요약이다. 소개문 key와 문장은 **신규 문안 제안**이며 아직 로컬라이징 데이터에 등록하지 않았다. 자유 전직·신규 직업은 추가하지 않는다.

| 캐릭터 / 직업 컨셉 | 무기·핵심 메커니즘 | 소개문 제안 | 제안 key | 첫 데모 |
|---|---|---|---|---|
| 핀 / 견습 기사 | 한손검·방패 / 저스트 가드 후 패리 슬래시 | 방패로 빈틈을 만들고, 검으로 길을 연다. 이번에는 늦지 않겠다는 견습 기사. | `ui.character.fin.intro` | 우선 구현 대상 |
| 리라 / 사냥꾼 | 활 / 구르기 직후 헌터 마크 | 한 걸음 물러서서 한 발을 정확히. 사라진 스승의 흔적을 좇는 사냥꾼. | `ui.character.lyra.intro` | 후속, 선택 가능 표시 금지 |
| 모리 / 견습 마법사 | 지팡이 / 서로 다른 속성 연속 적중으로 주요 융합 6종 | 말끝은 흐려도 마법은 선명하게. 두 속성을 잇는 견습 마법사. | `ui.character.mori.intro` | 후속 |
| 브람 / 드워프 대장장이 | 대형 해머 / 3단 차지·필드 간이 제작 | 한 번 더 달구고 묵직하게 내리친다. 손으로 쓸모를 만드는 대장장이. | `ui.character.bram.intro` | 후속 |

리라·모리·브람의 3계열 명칭이나 세부 노드는 이 문서에서 확정하지 않는다. 브람은 수리가 아닌 제작이며 내구도 시스템을 새로 넣지 않는다.

## 3. 첫 실행 테스트에서 먼저 검증할 핀의 기본 행동

여기서 말하는 전투 실행 검증은 **후속 본 게임 통합 테스트**다. 현재 `prototypes/fin-front-test`는 정면 모션·이동·충돌만 검증하며, 아래 공격·가드·스킬이 포함되지 않는다.

다음은 새 SP 스킬이 아니라 **기존 기본 조작**이다. 스킬 트리 습득으로 잠그지 않는다. 수치는 `game/data/combat.json` 참조이며 이 문서가 새 단일 소스가 되지 않는다.

| 행동 | 확인된 기준값 | 초심자 안내 문안 제안 | 확인할 장면 |
|---|---|---|---|
| 기본 공격 | 3타, 배율 1 / 1 / 1.5 | 검을 이어 휘둘러요. 마지막 공격 뒤에는 잠깐 빈틈이 생겨요. | 제자리·이동 후 공격의 방향 및 실제 적중 |
| 구르기 | 무적 0.3초, 전체 0.45초, 기본 비용 20 | 위험한 순간에는 굴러서 빠져나오세요. 스태미나도 살펴보세요. | 예고 공격 회피, 부족 시 거절 |
| 가드 | 일반 가드 피해 비율 0.2, 피격당 비용 10(기존 잠정값) | 방패를 들면 피해를 줄일 수 있어요. 막을 때 스태미나를 써요. | 일반 가드·고갈·가드 불가 공격 구분 |
| 저스트 가드 | 0.1초 창, 적 경직 0.4초(기존 잠정값) | 공격이 닿기 직전에 방패를 들어 보세요. | 성공 시 무피해·무소모·경직 요청 |

안내문 key 제안: `tutorial.fin.combo`, `tutorial.fin.roll`, `tutorial.fin.guard`, `tutorial.fin.just_guard`. 수치·키 바인딩은 최종 UI에서 데이터/입력맵으로 표시한다. 현재 `project.godot`의 스킬 키는 **Q/R**이며, GDD의 Q/E 표기를 그대로 복사하면 상호작용 E와 충돌한다.

패리 슬래시는 기존 기획을 계승하지만 **현재 실행 테스트에서 작동한다고 안내하지 않는다**. 구현할 때 저스트 가드 성공 → 반격 대기 → 공격 입력 → 1회 소모 순서를 별도로 검증한다. 자동 반격으로 바꾸지 않는다. 반격 창·배율·스태미나·쿨타임의 확정 테이블은 없어 여기서 숫자를 창작하지 않았다.

## 4. 핀 1단계 6노드 — 콘텐츠 제안

**전체가 미채택 제안**이다. 기존 3계열 구조의 첫 단계만 채우는 검토안이며 36노드 완성본이 아니다. 각 cost_sp=1은 QA 검토용 잠정값이고 실제 파일에 쓰지 않았다. 첫 단계이므로 선행 단계 없음. 확정 구조대로 다음 단계는 이전 단계 1포인트 이상 투자 시 열린다. 새로운 레벨 제한·양자택일 잠금은 추가하지 않는다.

| 제안 node_id | 계열 / 위치 | 표시 이름 | 유형 | 효과 방향 제안 | 설명 문안 제안 |
|---|---|---|---|---|---|
| `fin_sword_t1_1` | 검술 / 1 | 전진 베기 | 액티브 | 짧은 전진을 동반하는 단일 근접 공격. 벽 통과·순간이동·무적 없음 | 한 걸음 파고들며 벱니다. |
| `fin_sword_t1_2` | 검술 / 2 | 마무리의 기본 | 패시브 | 3타 피니셔의 공격 효과 강화. 공격 판정 횟수는 그대로 | 마지막 한 타를 더 확실하게. |
| `fin_guard_t1_1` | 수호 / 1 | 방패 밀치기 | 액티브 | 가까운 적을 밀어 공간 확보. 보스에게 강제 넉백 보장 안 함 | 방패로 앞을 밀어 숨 돌릴 틈을 만듭니다. |
| `fin_guard_t1_2` | 수호 / 2 | 단단한 자세 | 패시브 | 일반 가드 피격 스태미나 비용 경감. 저스트 가드 창 확장 아님 | 막을 때 드는 힘을 아낍니다. |
| `fin_chivalry_t1_1` | 기사도 / 1 | 숨 고르기 | 액티브 | 짧은 준비 후 스태미나 회복. 피해를 받으면 준비 중단 | 잠깐 자세를 고쳐 다음 움직임을 준비합니다. |
| `fin_chivalry_t1_2` | 기사도 / 2 | 버티는 마음 | 패시브 | 기존 VIT 최대 HP 효과를 바탕으로 생존 여유 제공 검토. 자동 부활 없음 | 한 번 더 일어설 힘이 아니라, 한 번 더 버틸 힘. |

로컬라이징 key 규칙 제안: `skill.<node_id>.name`, `skill.<node_id>.description`. 효과의 배율·거리·회복량·소모량·쿨타임은 **미정**이다. 이미 잠정값이 많은 기본 전투에 검증되지 않은 숫자를 추가하지 않기 위해, 초안 검토 후 `skills.json` 스키마와 실행 소비자를 함께 만들 때 정한다. 액티브만 두 슬롯 장착 대상이다.

### 탐험 자유도와의 연결 제한

- 두 진입 경로 중 하나를 특정 SP 스킬로만 열지 않는다. 처음 잘못 투자했다는 이유로 진행이 막히지 않아야 한다.
- 전진 베기로 낭떠러지나 벽을 건너는 기능, 방패 밀치기로 퍼즐 상자를 미는 기능은 **본 제안에 포함하지 않는다**. 이동·오브젝트 시스템 범위가 커지므로 필요하면 별도 기획 결정을 받는다.
- 첫 구간 재사용 보상은 스토리/레벨 담당의 도구·정보 설계와 연결한다. 여기에 새 성물이나 새 도구를 중복 발명하지 않는다.

## 5. 성장 도입 순서 제안

1. 첫 실행 테스트: 기본 공격·구르기·가드·저스트 가드의 읽힘과 손맛을 검증. 미구현 스킬에 작동하는 것처럼 버튼/설명 붙이지 않음.
2. 후속 스킬 구현: 패리 슬래시를 기존 고유 메커니즘으로 완성한 후 위 1단계 노드의 명칭·효과 검토. `characters.json`/`skills.json` 생성은 별도 구현 단계.
3. SP 연결: `pending_skill_points`를 지갑에 이관할 때 보상 중복·저장/로드·환불 테스트. 퀘스트를 반복 로드해 SP가 늘어나면 실패.
4. 레벨 곡선·스탯: 기존 레벨당 SP 1/스탯 3 유지. 존재하지 않는 경험치 곡선을 가정해 '20분에 레벨 3 보장' 같은 보상 일정을 확정하지 않음.
5. 리셋: 기존 사제 전체 리셋·레벨×100G 유지. 무료 리셋·필드 전직은 제안하지 않음. 초반 비용 적정성은 실제 획득 골드 측정 후 검토.

## 6. 구현 전 QA·결정 경계

- [ ] 실제 입력맵으로 안내 키를 표시한다(Q/R과 과거 Q/E 불일치 해소).
- [ ] 기본 행동과 SP 스킬을 구분한다. 가드·구르기를 실수로 습득 조건에 넣지 않는다.
- [ ] 가드 성공만으로 패리 슬래시 피해가 발생했다고 표시하지 않는다.
- [ ] 액티브 잠금/미장착/쿨타임/스태미나 부족 시 소비·피해 없음.
- [ ] 전진·넉백은 월드 좌표 배율과 충돌에 맞춰 검증한다. FHD 화면 픽셀과 전투 거리를 혼동하지 않는다.
- [ ] 미구현 계수와 실제 반영 수치를 스탯 UI에서 구분한다.
- [ ] SP 습득·저장·환불로 포인트 복제 또는 유실이 없다.
- [ ] 미구현 3인은 소개 자료일 뿐 실제 선택 가능한 캐릭터로 표시하지 않는다.

**현재 즉시 필요한 사용자 결정은 없음:** 기존 구조를 보존하는 문서 초안이며 실게임 효과를 바꾸지 않았다. 새 전직, 자유 직업 변경, 블록 전투, 파티/가챠, 필수 스킬 게이트가 필요해지는 경우 해당 작업을 멈추고 결정을 요청한다. 위 신규 6노드를 실제 적용하기 전에는 명칭·효과 및 수치 검토를 별도 진행해야 한다.
