## 0. 진입 경로 (사실 확인 — 코드 근거)

- 현재 유일한 "대사형" 팝업은 `QuestNpcPanel`(`game/scripts/ui/quest_npc_panel.gd`)이며,
  이것은 **퀘스트 수락/완료 전용**이다(제목+본문+확인/닫기 버튼 2개, 선택지 없음,
  타이프라이터 없음, 초상 슬롯 없음). 일반 NPC 잡담·컷신 대사에 쓸 풍선은 아직 없다.
- `game/project.godot`는 `addons/dialogue_manager`(bramwelt Dialogue Manager, autoload
  `DialogueManager`)를 플러그인으로 활성화해 두었지만, 실제 호출부는 `events.gd`의 주석
  1줄("다이얼로그 매니저 연동은 이후")뿐이다 — **미배선 상태**. 이 애드온의
  `example_balloon`이 초상+타이프라이터+선택지 구조의 참고 사례로 이미 리포에 있으나,
  채택 여부는 결정 필요(§6-A)로 남긴다.
- `docs/brd/04-decisions.md` D-145: 앞으로의 7단계 로드맵에 "대사 시스템"이 별도
  항목으로 예정되어 있다. 즉 이 문서는 그 단계의 **선행 설계**다.
- `UiRoot`(`game/scripts/ui/ui_root.gd`)는 인벤토리·대장간·우편함·QuestNpcPanel
  4개를 "전체화면 UI"로 취급해 상호배타 + `get_tree().paused` + `hud.visible=false`를
  한 곳에서 강제한다. 대사 풍선을 이 집합에 넣을지는 §3에서 다룬다.

## 2. 입력 매핑 (패드/키마/마우스)

| 동작 | 게임패드 | 키보드 | 마우스 | 동작 내용 |
|---|---|---|---|---|
| 확인 = 다음/스킵 | A (`ui_confirm`) | Enter (`ui_confirm`) | 좌클릭(풍선 패널 영역) | 타이프라이터 진행 중이면 **즉시 전체 텍스트 표시**(스킵), 완료 상태에서 누르면 **다음 줄로 진행**. 선택지가 떠 있으면 이 입력은 "현재 포커스 선택지 확정"으로 의미가 바뀐다(포커스가 항상 1개 존재 — wireframes §0.1 원칙) |
| 취소 = 건너뛰기 여부 | B (`ui_cancel`) | Esc (`ui_cancel`) | 우클릭 **(제안, D-196 우클릭=닫기 관례 재사용)** | 선택지가 없는 일반 대사: 홀드 여부 미정(§6-C) — 짧게 누르면 무시(대사 임의 종료 금지, 서사 사고 방지)로 잠정 설계. 선택지가 있는 분기 대사: `ui_cancel` 무효화(선택 필수) **(제안)** |
| 상하 = 선택지 이동 | 십자키/좌스틱 상하 (`ui_up`/`ui_down`, Godot 기본값 — project.godot에 재정의 없음) | ↑↓ | 마우스 오버로 포커스 이동(호버 전용 오픈 금지 원칙은 유지 — 오버는 포커스 이동만, 확정은 클릭 필요) | 선택지 목록에서만 유효. 좌우(`ui_left`/`ui_right`)는 사용하지 않음(세로 목록) |
| 마우스 클릭 | — | — | 좌클릭: 포커스 이동 없이 클릭한 선택지 즉시 확정(D-196 인벤토리 그리드의 `gui_input` + `MOUSE_BUTTON_LEFT` 패턴 재사용) | 각 선택지 행에 `gui_input` 연결, `event is InventoryMouseButton and pressed and button_index==MOUSE_BUTTON_LEFT` |

- 타이프라이터 진행 중 상하 입력은 무시한다(아직 선택지가 나타나지 않았으므로).
- `interact`(E, 필드 상호작용 키)는 대사 풍선이 열려 있는 동안 `ui_confirm`과 동일하게
  취급할지 여부는 결정 필요(§6-D) — `quest_npc_panel.gd`는 이미 `interact`/`menu` 둘 다
  확인으로 받는다(현재 코드 사실). 일반 대사도 같은 관례를 따르는 편이 일관적이다.

## 3. 전체화면 UI 규칙과의 관계 (HUD 숨김 · pause · 입력 차단)

**사실**: `UiRoot._recompute_paused()`는 인벤토리/대장간/우편함/QuestNpcPanel 중
하나라도 열리면 `get_tree().paused = true` + `hud.visible = false`를 함께 건다
(`process_mode = PROCESS_MODE_ALWAYS`인 UI 트리만 계속 입력을 받음).

대사 풍선은 이 4개와 **성격이 다르다** — 필드 위에서 진행되는 짧은 상호작용이고,
컷신/이동 연출과 동시에 굴러갈 수 있어야 하는 경우가 많다(RPG 관례). 그대로
`paused=true`를 걸면 대사 중 컷신 이동이나 배경 몬스터 AI가 함께 멈춰 부자연스러울
위험이 있다. 반대로 `paused=false`로 두면 대사 중 플레이어가 이동/공격해
`ui_confirm`과 이동 키가 동시에 먹히는 문제가 생긴다.

**설계 원칙(제안, 결정 필요 — §6-E)**:
1. 풍선이 열리면 **플레이어 이동·전투 입력만 차단**한다(플레이어 컨트롤러 쪽에
   `dialogue_active` 같은 플래그를 추가로 두는 안 — 이 문서 범위 밖의 코드 변경).
   `get_tree().paused`는 걸지 않아 배경 연출(다른 NPC 이동, 이펙트)은 계속 돈다.
2. HUD는 **숨기지 않는다**(퀵슬롯/스킬 슬롯이 대사 중에도 의미가 있는 정보는
   아니지만, 화면 하단이 풍선 패널에 가려지므로 별도로 `hud.visible=false`를
   걸 필요가 없다 — 풍선이 그 위에 그려지는 배치이므로 시각적으로 자연히 가려짐).
   단, HP/스태미나(좌상단)는 대사 중에도 보여 전투 중 대사(예: 보스 전 컷신)에서도
   위험 신호가 끊기지 않게 한다.
3. `menu`/`quest_log`/대장간·우편함 오픈 입력은 대사 중 무시한다(`UiRoot`의 기존
   상호배타 목록에 "대사 진행 중" 조건 하나를 추가하는 형태 — `is_dialogue_open()`,
   **확정·구현 완료, D-256** — 결정 필요 항목이 아니다).
4. 예외: 퀘스트 수락/완료를 겸하는 대사(현재 `QuestNpcPanel`이 담당하는 영역)는
   지금처럼 `paused=true` 경로를 유지한다 — 이 문서의 풍선은 **잡담·컷신·연출용
   순수 대사**를 대상으로 하고, 선택 결과가 퀘스트 상태를 바꾸는 분기 대사는 원칙적으로
   범위 밖이다. **예외(v0.2, D-255)**: 브리지 어휘를 통해 퀘스트 상태를 바꾸는 분기
   대사(`docs/specs/dialogue-system-v1.md` §8 몽실이 예시 — `QuestObject.resolve_branch_outcome()`
   을 접두어 없이 호출)는 이 풍선 위에서 허용한다. 이 예외는 `converges: true`(보상이
   갈리지 않는 분기, D-94) 데이터에서만 검증됐다 — 보상이 갈리는 분기까지 자동으로
   허용하는 것은 아니다(§6-A에서 `QuestNpcPanel`과의 장기 통합 여부를 결정 항목으로 남김).

## 4. 상태 목록

| 상태 | 조건 | 표시 |
|---|---|---|
| 타이핑 중 | 줄 진입 직후 ~ 전체 글자 출력 완료 전 | 본문 글자 순차 출력, 선택지 영역 비어 있음, 하단 가이드 `(A)스킵` |

| 선택 확정 직후 | 선택지 클릭/확정 입력 | 선택지 영역 제거, 다음 줄로 즉시 진행(전환 애니메이션 없음 **(제안)**) |

| 이름 없음(내레이션) | 화자가 없는 지문/독백 | 이름표 숨김, 초상 슬롯 접힘 → 본문 폭 확장(§6-B 결정 필요) |
| 초상 미보유 NPC | 초상 아이콘 데이터 없음 | 64×64 회색 placeholder(단색+테두리, 작업 규칙 4) — 빈 칸 노출 금지 |

| 640×360 이하 폭(웹 축소 창) | 브라우저 창이 정수 배율 미만으로 축소 | Godot `stretch/mode=canvas_items`+`scale_mode=integer`가 레터박스 처리 — 풍선 좌표는 항상 640×360 논리 좌표 기준이라 별도 대응 불필요(사실, `project.godot` 확인) |

| 선택지 포커스 하이라이트 | `theme.get_stylebox("focus_highlight", "Inventory")` 또는 `theme.get_color("focus", "Inventory")` | 인벤토리 슬롯 포커스와 동일 시각 언어 |

**각주(⑪-1 결함 수정, 신규 키 1건)**: 선택지 목록이 `(128,296)~(592,344)`(48px, 4개 하드
상한)에 고정돼 있어 본문 폰트(`HUD/font_sizes/default`=11, 줄당 약 14.7px)를 그대로
쓰면 4개가 못 들어간다(실측: 11px 그대로면 마지막 버튼이 y=352까지 내려가 8px 초과).
`Dialogue/font_sizes/response`(9)를 새로 추가해 응답 버튼에만 적용한다 — 위 표의
"재사용" 원칙에 대한 유일한 예외이며, 큰 글자 접근성 설정은 아직 배선하지 않았다
(`dialogue_balloon.gd` 완료 보고 TODO, §6 "큰 폰트에서도 3줄이 들어가는지 검증 필요"와
같은 이유로 응답 목록도 후속 검증 대상).

## 6. 접근성

- **글자 크기**: 위 표의 `Settings.font_size_large` 2단계를 그대로 상속(신규 설정 불필요,
  기존 `Events.settings_changed` 구독 패턴 재사용). 큰 폰트에서도 본문 3줄이 §1 영역
  안에 들어가는지는 실제 구현 시 검증 필요 — 안 들어가면 패널 높이가 아니라 **줄 수를
  줄이는(콘텐츠 측 대사 분량 조정)** 방향을 우선한다(패널이 커지면 §1 하단 여백/HUD
  겹침 가정이 깨짐).
- **자동 진행 옵션**: 현재 `game/scripts/core/settings.gd`에는 `screen_shake_index`,
  `colorblind_mode`, `font_size_large` 3개만 있고 자동 진행 관련 필드가 없다(사실,
  코드 확인) — 신규 설정 항목(`dialogue_auto_advance: bool` 등)이 필요하므로 이는
  **결정 필요 항목**이며 코드 변경(설정 화면 §10 wireframes 항목 추가 포함)이 따른다.
- 색약 모드(`colorblind_mode`)는 이 화면에 등급 색이 없어 직접 영향은 없음(사실 —
  대사 풍선에는 Rarity 색상 체계를 쓰지 않는다). 단, 선택지 잠금 표시(위 "비활성"
  행)에 색만으로 구분하지 않도록 자물쇠 아이콘 등 형태 요소를 병행한다(wireframes
  §0.2 "색+아이콘 이중 채널" 원칙 재적용).
- 화면 흔들림 강도는 이 화면과 무관(대사 중 흔들림 이벤트가 겹치는 컷신 연출은
  범위 밖).

## 7. 웹 데모 터치

- `game/export_presets.cfg`에 web 프리셋이 있고(사실, 확인), `progressive_web_app`은
  비활성. `project.godot`에는 터치→마우스 에뮬레이션 설정(`input_devices/pointing/
  emulate_mouse_from_touch`)이 별도로 재정의되어 있지 않다(사실 — grep 결과 없음),
  즉 Godot 기본값(터치가 마우스 이벤트로 에뮬레이트됨)이 적용된다.
- 이 전제하에 §2 "마우스 클릭" 행이 웹 터치 조작을 그대로 커버한다: 화면 탭 = 좌클릭
  = 확인/선택지 확정. 별도의 터치 전용 UI(가상 패드, 탭 존)는 이 화면에서 추가하지
  않는다 — 풍선 자체가 이미 탭 하기 충분히 큰 영역(패널 전체 560×96)이라 스킵/다음
  탭에 정밀도 문제가 없다.
- 선택지 행(세로 16px)은 손가락 탭 기준으로는 좁을 수 있다 — 데스크톱 640×360을
  정수 배율(예: 3배=1920×1080)로 스케일해 표시하므로 실제 화면상 16px×3=48px가
  되어 일반적인 터치 타깃 최소 권장치(약 44px)를 충족한다(계산 근거: `project.godot`
  `window_width_override=1920`/`viewport_width=640` → 배율 3배). 모바일 브라우저에서
  더 작은 배율(정수 배율 미만)로 렌더될 경우의 타깃 크기는 별도 검증 필요 **(결정
  필요 없음 — QA 검증 항목으로만 남김)**.
