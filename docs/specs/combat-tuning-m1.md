# M1 전투 수치 확정안

> 기준 문서: `docs/GDD-도트액션RPG-기획안.md` 4장(전투)·5장(성장), `docs/brd/03-features/02-전투.md`(R2), `docs/brd/04-decisions.md`(D-05·D-08)
> 대상 데이터: `game/data/combat.json` (읽기 전용 참조, 반영은 godot-engineer)
> 목적: `combat.json`의 `_balance_todo` 제안값을 M1 게이트(외부 테스터 10인 "타격감 4/5 이상") 기준으로 확정 또는 유예한다.
> 표기: **확정** = 이번 문서로 값 고정 / **M1 플레이테스트 후 결정** = 현재는 제안값 유지, 실측 후 재조정

## 0. 공통 전제

- 모든 프레임 수치는 60fps 기준(GDD 4.1), 구현은 delta 기반.
- 프로토타입 자산은 **16px 타일(Ninja Adventure) + 카메라 줌 2**를 사용한다. 최종 아트는 32px 타일이므로, "월드 픽셀" 단위 수치는 최종 전환 시 **×2 재환산**이 필요하다 (`combat.json`의 `_comment`가 이미 지적한 부분 — 본 문서 1절에서 검증한다).
- 데미지 공식(M1 한정, 방어력 감산 없는 단순 모델):
  ```
  hit_damage = player_base_attack × combo.damage_multipliers[hit_index] × element_multiplier
  ```
  - `player_base_attack` = 10 (레벨1, 무기 미장착 기준 임시값 — `characters.json` 확정 전까지 `game/scripts/tuning.gd`에만 존재해야 하는 임시 상수, GDD 12장 규칙 준수)
  - `element_multiplier` = 1.5 (상성 적중 시, D-08) / 1.0 (기본)
  - 몬스터 방어력 감산은 M1 범위 밖 (아래 "결정 요청 8" 참고)

## 1. 이동속도 — 80px/s (확정, 프로토타입 스케일 한정)

**목표**: 손맛 검증 단계(M1)에서는 "반응성"이 "월드 스케일 정합성"보다 우선한다. 화면 크로스 타임으로 반응성을, GDD 7.1 도보 횡단 25분 주장으로 스케일 정합성을 각각 검증한다.

### 1-1. 화면 크로싱 타임 (반응성 검증)
- 내부 렌더 해상도 640×360(GDD 9.1), 카메라 줌 2 → 화면에 보이는 월드 폭 = 640 / 2 = **320 world-px** (= 20타일, 16px 타일 기준)
- `walk_speed_px = 80` → 화면 폭 하나를 가로지르는 시간 = 320 / 80 = **4.0초**
- 초당 이동 타일 수 = 80 / 16 = **5타일/초**
- 판정: 4초/화면은 탑다운 액션 RPG 기준 스냅피한 편(참고: 젤다류 체감상 3~5초/화면대가 표준). **M1 손맛 기준으로는 채택**.

### 1-2. 최종 아트(32px 타일) 전환 시 재환산 검증
- 줌2×16px 타일의 화면상 겉보기 크기 = 32px → **이미 최종 32px 타일의 줌1 화면과 시각적으로 동일**하다. 즉 현재 세팅은 "다운스케일된 최종 아트 시뮬레이션"에 해당한다.
- 따라서 최종 전환 시 필요한 것은 체감 재조정이 아니라 **수치 변환**: `final_walk_speed_px = prototype_walk_speed_px × (32/16) = 160px/s` (줌1 기준). 화면 크로싱 타임은 4.0초로 그대로 유지된다 (검증 완료 — "느껴지는 속도"는 아트 교체와 무관).
- **godot-engineer 전달 사항**: `movement.walk_speed_px`는 "16px 타일 프로토타입 값"으로 명시하고, 최종 아트 교체 PR에서 ×2 배율 적용을 체크리스트에 넣을 것.

### 1-3. GDD 7.1 "도보 횡단 약 25분"과의 정합성 (불일치 발견)
- GDD 7.1: "전체 크기 약 400×400 타일 × 5개 지방", 지도상 배치는 세로 4지방(프로스트헤임-하틀랜드-브릿지포트-이그니스), 가로 3지방(엘드우드-하틀랜드-사마르).
- 최장 축(세로, 4개 지방)을 직선 최단 거리로 가정: 4 × 400타일 = 1,600타일 × 32px(최종 아트) = 51,200px
- 최종 속도 160px/s로 직선 이동 시: 51,200 / 160 = **320초 ≈ 5.3분**
- GDD가 명시한 "25분"과 **약 4.7배 차이**. 25분에 맞추려면 최종 속도가 약 34px/s(프로토타입 환산 17px/s)까지 떨어져야 하는데, 이는 초당 1타일(32px) 수준으로 액션 RPG 기준 명백히 굼뜨다(1-1의 스냅피 기준과 정면 충돌).
- **해석**: GDD의 "25분"은 지형·전투·분기·요격 몬스터 등을 포함한 "체감 탐험 시간"이지 순수 직선 주파 시간이 아닐 가능성이 높다. 다만 이 판단은 레벨 디자인/월드 스케일 소관이라 전투 기획 단독으로 확정할 수 없다.
- **조치**: 이동속도 80px/s(프로토타입) / 160px/s(최종)는 **손맛 기준으로 확정**한다. 월드 스케일 표현("25분")과의 불일치는 결정 요청 목록으로 상위 이관한다(§9-1).

| 항목 | 값 | 근거 |
|---|---|---|
| `movement.walk_speed_px` (16px 프로토타입) | **80.0** (확정) | 화면 크로싱 4.0초, 5타일/초 |
| 최종 아트 환산값 (32px, 줌1) | **160.0** (계산값, M2 아트 전환 시 적용) | ×2 재환산 |
| 검증 방법 | 플레이테스트에서 "이동이 답답하다" 응답 비율 측정, 20% 초과 시 재조정 |

## 2. 구르기 — 0.45s / 48px / 무적 0.3s (확정)

**목표**: 무적시간(GDD 확정 0.3초)을 살리는 전체 지속시간·이동거리를 정해 "회피가 항상 유효한 해답"(GDD 4.2 원칙 2) 조건을 수치로 보장한다.

### 2-1. 무적 비중
- 무적 0.3s / 전체 0.45s = **66.7%**가 무적 구간, 나머지 0.15s(33.3%)는 후딜레이(착지 경직) — 구르기를 "포지셔닝 목적"으로만 쓸 때 노출되는 대가로 기능한다.

### 2-2. 적 예고(0.5초)와의 관계 — 유효 회피 입력 창 계산
- 적 공격 예고 시작을 t=0, 적중을 t=0.5s로 고정.
- 플레이어가 구르기를 t0 시점에 입력하면 무적 구간은 [t0, t0+0.3].
- 적중 시점(0.5s)이 이 구간에 포함되어야 회피 성공: `t0 ≤ 0.5 ≤ t0+0.3` → **0.2s ≤ t0 ≤ 0.5s**
- 즉 예고 시작 후 **0.2초~0.5초 사이(폭 0.3초, 예고 전체의 60%)** 언제 입력해도 회피가 성립한다. 평균 인간 반응시간(학습된 패턴 기준 0.15~0.25초)을 감안하면 예고를 보고 반응해도 여유가 있는 관대한 창 — GDD 11장 "캐주얼 지향" 톤과 부합.
- 반대로 t0 < 0.2s(너무 일찍 구름)로 입력하면 무적이 적중 이전에 끝나 후딜레이(0.15s) 중 피격 위험 — "일찍 굴러도 안전하지 않다"는 스킬 표현 요소로 의도적으로 남긴다.

### 2-3. 이동 거리 대비 속도 — `movement.roll_speed_px`와의 불일치 (스키마 정리 필요)
- `roll.distance_px`(48) / `roll.duration_sec`(0.45) = 평균 **106.7px/s**
- 그런데 `combat.json`에는 별도로 `movement.roll_speed_px = 160.0`이 존재 — 두 값이 서로 다른 모델(거리·시간 보간 vs 등속 이동)을 동시에 참조하고 있어 **데이터 중복/모순**이다.
- **권장**: 구르기는 "고정 거리(48px)를 고정 시간(0.45s) 동안 이동"하는 거리·시간 모델로 통일하고, `movement.roll_speed_px`는 페기하거나 "가속 곡선의 첨두 속도(참고용, 검증 비대상)"로 재정의한다. godot-engineer 확인 필요(§9-2).
- 걷기 대비 구르기 평균 속도 배율 = 106.7 / 80 = **1.33배** — 버스트감은 있으나 압도적이지 않은 수준으로 적정.

| 항목 | 값 | 근거 |
|---|---|---|
| `roll.iframes_sec` | 0.3 (GDD 확정) | GDD 4.1 |
| `roll.duration_sec` | **0.45 (확정)** | 무적 66.7% + 후딜 0.15s 확보 |
| `roll.distance_px` | **48 (확정)** | 3타일(16px) 이동, 평균속도 106.7px/s |
| 유효 회피 입력 창 | 0.3s (예고의 60%) | §2-2 계산 |
| 검증 방법 | 플레이테스트에서 "예고 보고 굴렀는데 맞았다" 빈도 측정(목표 5% 미만), 조기 구르기 후 피격 빈도 별도 집계 |

## 3. 스태미나 — 최대 100 / 회복 25/s / 비용(구르기20·강공격25·가드피격10)

**목표**: "무한 회피 방지 + 라이트 유저도 자원관리로 극복 가능"(F2-3 근거)을 수치로 보장. 완전 고갈 페널티는 casual 톤(D-25 사망 페널티 상한 등)과 일관되게 과하지 않아야 한다.

### 3-1. 연속 구르기 가능 횟수
- `regen_delay_sec = 0.5s` > `roll.duration_sec = 0.45s` → 연속으로 구르기를 이어 붙이는 동안(각 구르기 간격 0.45s)에는 회복 딜레이가 끝나지 않아 **회복이 개입하지 않는다**.
- 100 / 20 = **정확히 5회** 연속 구르기 가능 (5회차 시작 시점 잔여 스태미나 정확히 20 → 소모 후 0). 6회차는 발동 불가(스태미나 바 적색 점멸).
- 5회 연속 구르기 소요 시간 = 5 × 0.45s = **2.25초**의 완전 무적 회피 구간 확보 — 보스 발악 패턴 회피 등에 필요한 여유로 적절.

### 3-2. 완전 고갈 후 회복 딜레이 — 1.0초로 하향 확정 제안
- 현재 `combat.json` 제안값은 `exhausted_penalty_sec = 1.5`. 본 문서는 **1.0초로 하향**을 확정 제안한다.
- 근거(비교 계산): 고갈(0) → 재구르기 가능(20) 소요 시간 = `exhausted_penalty_sec + 20/25`
  - 1.5s 안: 1.5 + 0.8 = **2.3초** 동안 회피 수단 전무
  - 1.0s 안: 1.0 + 0.8 = **1.8초**
  - 적 예고(0.5s) 기준으로 환산하면 1.5s 안은 무방비 노출이 예고 약 4.6회 분, 1.0s 안은 약 3.6회 분. GDD 11장의 "실패 페널티 최소화" 기조 및 F2-3 "라이트 유저도 전략으로 극복"에는 1.0초 쪽이 더 부합.
  - 완전 회복(0→100)까지: 1.0s 안 = 1.0+4.0=**5.0초** / 1.5s 안 = 5.5초 — 완전 회복 체감 차이는 크지 않으므로, 하향에 따른 손실은 "직후 1회 재행동 가능 시점"에만 집중되고 이는 의도한 개선점과 일치.
- **결론**: `stamina.exhausted_penalty_sec`를 1.5 → **1.0으로 확정 변경**. godot-engineer가 `combat.json` 반영.

### 3-3. DEX 보정식 (구르기 소모량 경감, S2-1b 규칙)
```
roll_cost_effective = stamina.costs.roll × (1 − min(0.5, DEX / 300))
```
- DEX 50 → 16.7% 경감 (16.7 소모) / DEX 100 → 33.3% 경감(13.3 소모) / DEX 150 이상 → 상한 50% 경감(10.0 소모)
- 상한 근거: 스탯 포인트 총량(레벨50 도달 시 스탯 포인트 약 3×49=147 + 캐릭터 초기치, 한 스탯에 전부 투자해도 대략 150대)을 감안해 DEX 150을 "이론상 최대 DEX 몰빵" 기준점으로 잡고 그 지점에서 정확히 50% 경감이 걸리도록 계수(1/300)를 역산했다. 스태미나가 0이 되는 것을 막기 위해 50% 상한은 필수(무한정 경감 시 구르기 자원 관리 자체가 무의미해짐).
- **적용 범위**: BRD S2-1b는 "DEX가 소모량 경감"을 구르기에 한정해 명시한다. 강공격(`heavy_attack`)·가드(`guard_hit`) 비용에는 이 공식을 적용하지 않는다(§9-4 결정 요청으로 확장 여부 상위 이관).

| 항목 | 값 | 근거 |
|---|---|---|
| `stamina.max` | 100.0 (확정) | 구르기 5회 기준선 |
| `stamina.regen_per_sec` | 25.0 (확정) | 0→100 회복 4.0초 |
| `stamina.regen_delay_sec` | 0.5 (확정) | 구르기 캔슬 체인과 겹치지 않는 최소값 |
| `stamina.exhausted_penalty_sec` | **1.0 (확정, 1.5→하향)** | §3-2 |
| `stamina.costs.roll` | 20.0 (확정) | 연속 5회 |
| `stamina.costs.heavy_attack` | 25.0 (M1 플레이테스트 후 결정) | 강공격 사용 빈도 실측 필요 |
| `stamina.costs.guard_hit` | 10.0 (M1 플레이테스트 후 결정) | 가드 지속시간 실측 필요 |
| DEX 보정식(구르기 한정) | `cost × (1 − min(0.5, DEX/300))` (확정) | §3-3 |
| 검증 방법 | 평균 세션에서 스태미나 고갈 발생 빈도(목표: 5분당 1~2회), 고갈 후 이탈/짜증 반응 설문 |

## 4. 콤보 — 입력 버퍼 0.2s / 리셋 0.6s / 배율 1.0·1.0·1.5 / 3타 후딜레이(제안)

**목표**: 3타 콤보가 "누르면 이어진다"는 확신을 주면서, 3타(피니셔)에는 배율에 걸맞은 위험(후딜)을 부여한다.

### 4-1. 기존 값 확정
- `combo.input_buffer_sec = 0.2s`: 각 타 종료 전 0.2초 내 재입력 시 다음 타로 연결. 60fps 기준 12프레임 — 사람이 "느낌"으로 누르는 리듬(약 8~15프레임)에 들어맞아 **확정**.
- `combo.reset_after_sec = 0.6s`: 버퍼(0.2s)의 3배 여유 — "공격을 멈췄다"는 의도를 명확히 구분하는 임계치로 **확정**.
- `combo.damage_multipliers = [1.0, 1.0, 1.5]`: 3타 합 3.5배(평균 1.167배/타). 2타에서 멈추면 2.0배. 3타 끝까지 밀어붙일 유인(단순 곱연산 대비 +0.5배 보너스)이 명확해 **확정**.

### 4-2. 3타 후딜레이 (제안, M1 플레이테스트 후 결정)
- 제안값: **0.35초(21프레임)**, 그중 프레임 10(0.167s)부터 구르기 캔슬 허용(F2-1 스펙 "공격 애니메이션 특정 프레임 이후 구르기 캔슬 가능" 반영).

## 5. 가드 — 칩데미지 20% / 저스트 가드 6프레임(확정) / 성공 시 적 경직시간(제안)

### 5-1. 칩데미지 20%
- `guard.chip_damage_ratio = 0.2` → 가드는 피해의 **80%를 경감**한다.
- 스태미나 소모(가드 피격당 10, §3)와 겹쳐 계산하면: 완전 가드로만 버틸 경우 100/10 = 10회 피격까지 무너지지 않고 버틸 수 있으나, 그동안 누적 칩데미지는 `10 × (몬스터 공격력 × 0.2)`만큼 실제로 들어온다. 즉 가드는 "생존"은 보장하되 "무피해"는 아니다 — 구르기(무적, 대신 5회 제한)와 명확히 다른 트레이드오프를 형성해 **확정**.

### 5-2. 저스트 가드 6프레임(0.1초) — GDD 확정(D-05), 재확인만
- 이미 GDD/D-05로 확정된 값. 본 문서는 재확인만 하고 변경하지 않는다.

### 5-3. 저스트 가드 성공 시 적 경직시간(제안)
- 제안값: **0.4초(24프레임)**

- **M1 플레이테스트 후 결정**: 핀 전용 수치이므로 `characters.json` 확정 시점(핀 패리 슬래시 스펙)에 맞춰 함께 조정. 신규 키는 `guard.just_guard_enemy_stagger_sec`로 제안.

## 7. 퀵슬롯 십자키 순서 — 상/우/하/좌 = 1/2/3/4(시계방향) 확정

**배경**: GDD 4.1 "1~4 / 십자키", 와이어프레임 화면 3은 하단 중앙에 `[1포션×5][2폭탄×2][3음식][4-]`를 좌→우 1열로 배치한다. 십자키는 좌우상하 4방향뿐이라 좌→우 배열을 그대로 매핑할 수 없어 별도 규칙이 필요하다.

**결정**: **상=1, 우=2, 하=3, 좌=4 (시계방향, 위에서 시작)** 로 확정한다.

**근거**:
1. 예시 아이템 배치(1=포션, 2=폭탄, 3=음식, 4=빈칸)를 볼 때 1번(포션=생존 직결, 가장 자주·다급하게 눌러야 함)이 엄지가 가장 반사적으로 닿는 방향(위)에 있어야 한다. 다수의 액션 게임에서 "위 방향"이 회복 아이템 슬롯의 관용적 위치(예: 소울류의 R1+상 조합)인 것과도 일치.
2. 시계방향 순서는 학습 비용이 가장 낮은 배열(1→2→3→4가 항상 같은 회전 방향)이며, GDD 11장 "모든 UI는 게임패드만으로 완주 가능해야 한다" 요구와도 부합 — 방향 자체가 곧 순번이 되어 별도 암기 없이 직관적으로 유추 가능하다.
3. 4번(빈 슬롯, 예비용)이 왼쪽에 위치해 가장 덜 위급한 상황에서 접근하는 자리로 자연스럽게 배정된다.

| 방향 | 슬롯 번호 | 예시 아이템 |
|---|---|---|
| 상 | 1 | 포션 |
| 우 | 2 | 폭탄(투척물) |
| 하 | 3 | 음식(버프) |
| 좌 | 4 | (예비) |

- **검증 방법**: 패드 사용자 대상 "위급 상황에서 포션 슬롯을 찾는 데 걸린 시간" 측정(목표 1초 이내, 학습 후), 오조작(다른 슬롯 오입력) 빈도.
