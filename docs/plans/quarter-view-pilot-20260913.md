# 쿼터뷰 비교 파일럿 — 2026-09-13

사용자가 기존 게임을 보존한 작은 쿼터뷰 실제 플레이 샘플 제작을 승인했다. **본편 전체 전환, 3D 전환, 회전 카메라 채택은 승인한 것으로 간주하지 않는다.** 기존 탑다운 실행본과 저장 파일은 변경하지 않는다.

## 범위와 완료 기준

- 새 독립 Godot 프로젝트: `prototypes/quarter-view-lab`.
- 고정된 비스듬한 2D 시점, 마을 입구 한 구역, 적 한 마리. 정확한 등각 격자 사용 여부는 구현 선택이며 본편 규격 확정이 아니다.
- FHD1920×1080 화면. 전체화면과 창 모드를 구분하고 실제 캡처 크기 및 화면 모서리를 확인한다. 과거 FHD 결과를 신규 샘플 결과로 재사용하지 않는다.
- 길/건물 발밑 충돌, 앞뒤 가림, 이동, 한 번의 기본 공격을 실제 실행한다. 준비→타격→회수 시간과 보이는 검의 영역/피해 발생 구간을 맞춘다.
- 피해량·넉백·공격 시간은 샘플 전용 설정이며 본편 경제·전투·직업 데이터에 반영하지 않는다. 저장/전직/퀘스트 시스템을 이 샘플에 임의 이식하지 않는다.
- 승인된 핀 외형·몸체64×96는 목표 유지. **완성된 새 방향별 핀 모션은 아직 확보하지 못했다.** 기존 기사는 시점·판정 비교용 임시 배우일 뿐 핀 모션 완료 증거가 아니다. 거절된 다리 절단/압축·정지 그림 흔들기를 재사용하지 않는다.
- 새 환경 그림은 실제 게임에 로드하되, 배경 한 장과 충돌·가림 영역을 수동 대응한 작은 시험이다. 전체 타일 제작 시스템 또는 완성된 확장 월드가 아니다.

## 1차 샘플 준비 이력 — E37

독립 샘플 1차 실행 준비 완료 당시 기록이다. 아래37검사/56파일은 E37 이력이며, 후속 공격 조정 이력 E38의50검사/62파일과 손 연결 E39의58검사/70파일은 각각 다음 절을 따른다. [실행 안내](../../prototypes/quarter-view-lab/README.md), [1차 QA](../qa/quarter-view-lab-20260913.md).

- 새 마을 배경 1장(1672×941 RGB 원본)을 FHD1920×1080 화면에 표시한다. 타일셋·정밀 도트 원화 완료가 아니다.
- 동일 최종 소스의 정상 import, 실제 Main 11검사, 전투 fixture 37검사, GUI/입력/가림 19검사 모두 자연 종료/native 0. 준비 목록 56파일과 엔진 EXE 2개 SHA를 검증했다. 개수는 사용자 플레이 시나리오 수가 아니다.
- 독립 DA 필수 수정 0건. root가 실제 FHD 캡처에서 화면 채움·HUD·배경과 임시 배우의 스타일 차이를 확인했다. 나무 가림은 근사 다각형이며 QA의 앞뒤 위치 주입 비교이지 전체 이동 경로 검증이 아니다.
- 기존 game/실행기/세이브를 편집하지 않았다. 샘플은 매 실행 새 격리 폴더를 쓰며 저장/불러오기가 없다.
- **새 핀64×96 방향별 보행·공격 원화는 여전히 미완료**다. 기존 작은 기사/슬라임 대역과 새 배경의 밀도 차이가 크며 이 미술 통일 문제가 다음 주요 작업이다. 실제 타격감의 사용자 평가와 소리 청취도 남아 있다.

다음 판단은 이 샘플의 시점·공간감·조작을 비교한 뒤 한다. 본편 전체 쿼터뷰 전환이나 최종 미술 품질 승인을 이 실행 결과로 대체하지 않는다.

## 사용자 플레이 피드백 — 공격 반응 후속 조정

사용자: “조작과 공간감은 너무 좋은데, 공격 모션이 어색하고, 타격 타이밍이 조금 늦은 감이 있어.”

- 조작·공간감은 긍정 평가로 기록하되 본편 전체 시점 이관 승인으로 확대하지 않는다.
- 같은 샘플의 공격 준비 시간·검의 가속/회수 표현·피해 시점만 조정한다. 배경·맵·이동 속도·기존 본편/저장은 유지한다.
- 기존 110ms 준비+100ms 선형 타격+230ms 회수와 변경안을 같은 거리/방향/물리 시간 조건에서 비교한다. 준비 설정값과 실제 정면 접촉 시점은 구분한다.
- 새 검 표현은 엔진 도형 렌더링이며 새 bitmap이나 완성된 핀 몸체 애니메이션이 아니다. 다리 절단·확대/압축·몸체 흔들기로 원화 제작을 대체하지 않는다.
- 담당: 전투 구현/회귀 명세(npc_runtime), 실제 실행/화면/보고(save_verification), 독립 검수(art_review), 범위/최종 확인(root). 새 결과는 검증 후 별도 QA에 기록한다.

후속 실행 결과: 준비50ms/활성85ms/회수140ms(무타격 총275ms), 빠르게 나가는 검·짧은 잔상·후반 회수/기본 자세 복귀로 조정했다. 보존된 구 공격 로직의 동일62px/8방향/60Hz 재연에서 첫 피해는166.667→66.667ms였고, 실제 Main 입력 주입의 동기 피해 신호는4물리프레임에 발생했다. 둘 다 하드웨어 지연 계측이 아니다. 정상import/Main11/전투50/일반GUI19/공격GUI10 검사 후 새 ready62파일/엔진2SHA를 준비했다. 상세·원본 로그: [공격 피드백 QA](../qa/quarter-view-attack-feedback-20260913.md).

root가 준비·접촉·후반 회수의 엔진 내3배 확대 PNG3장을 직접 확인했다. 검과 접촉 표시/HP감소, 기본 자세 복귀는 보이나 구형 배우의 원화 수와 손/무기 연결 표현의 한계는 남는다. 이 세 정지 장면으로 연속 모션의 최종 자연스러움이나 완성된 핀을 승인하지 않는다. world/layout/Main/project/배경/기사·슬라임 원본의7개SHA는 이번 작업 전후 동일하다(본편 전체 파일 감사와는 구분).

## 손과 무기 연결 후속 — 진행 범위

사용자가 “여전히 손에 무기를 들었다는 느낌은 아니지만 타격감은 훨씬 좋아졌어”라고 평가했고 손 위치/공격 자세/무기 궤적 연결 개선을 이어서 진행하도록 요청했다.

- 긍정 평가한 공격 시간50/85/140ms·피격정지65ms·피해15·이동230 설정을 유지한다. 손 기준점 이동이 실제 접촉 시간/사거리에 미치는 영향은 별도 검사하고 숨기지 않는다.
- 기존 기사 방향별 원화의 손 좌표를 근거로 손잡이를 연결하고, 손/무기/몸체의 앞뒤 순서 및 평상시 무기를 든 표현을 개선한다.
- 원본 캐릭터 PNG를 절단하거나 몸체를 흔들고 늘리는 방법은 사용하지 않는다. 기존 원화의 팔 자세 수가 부족한 한계와 완성된 핀 전용 원화 제작은 분리한다.
- 아트 담당의 소켓 명세, 전투 담당의 연결/판정 구현, 엔진 담당의 실행·화면 검증을 서로 교차 검토한다. 새 화면은 사용자에게 공유하고 본편·세이브·맵·배경·실제 카메라는 바꾸지 않는다.

구현: [기존 원화 소켓 명세](../art/preview/quarter-view/weapon-sockets-v1.md)를 사용해 방향별 대기/걷기/공격의 손 위치와 손잡이를 연결했다. 위 방향은 무기→몸체→원본 장갑, 나머지는 몸체→무기→원본 장갑 순서다. 검 실체는 대기/준비/타격/회수에 계속 보이며 그림과 타격 판정의 원점도 같은 손 위치를 따른다. 원래 작은 장갑 영역을 원래 좌표에 다시 그릴 뿐 PNG를 절단/편집한 새 애셋은 아니다.

초기 실행에서 정면62px 최초 피해는4물리프레임을 유지했다. 다만 아래·좌상·우상 방향은 손 위치 변화로4→5프레임(66.667→83.333ms)이 됐다. 다른5방향은4프레임이다. 이는 고정60Hz의 동일거리 논리 재연이며 하드웨어 지연 측정이 아니다. 설정된 검 길이/시간이 동일해도 손 원점 이동 때문에 몸 중심에서 본 도달 영역이 같다는 뜻은 아니다. 수치나 사거리를 몰래 보정하지 않았다.

root가 실제 공격3장과 네 방향×두 자세의 엔진 렌더 격자를 직접 확인했다. 그립이 원화 손에 겹쳐 보이고 검이 회수 후에도 남는다. 그러나 이것은 기존 소수의 팔 포즈를 연결한 개선이며 부드러운 다프레임 팔/몸통 원화·새 핀64×96 제작 완료가 아니다. 임시 대역의 손 사용 방향을 핀의 승인된 오른손 검/왼손 방패로 오인하지 않는다. 최종 실행 근거와 연속36 readback 재생기는 [손–검 QA](../qa/quarter-view-weapon-grip-20260913.md)에 기록한다.

최종 준비: 정상import/Main11/전투58/기존GUI19/공격연속GUI12/정적격자18 검사, ready70파일과 엔진2SHA. root가 최종 격자 화면 및 VerifyOnly(native0)를 직접 확인했다. 최초 격자의 잘린 칼끝은 QA 배치를 수정해 최종 화면에서 확인했고, 벽 검사는 마지막 실행에서 실제 active 손 소켓으로 맞췄다. HTML 재생기는36개 실제 캡처를 사용하며 Node mock8그룹은 검사했으나 실제 브라우저 재생은 아직 검증하지 않았다. 손/손잡이 같은 API 좌표의 오차0은 배선 계약 검사이며 원화 손의 시각적 검증과 구분한다. root 별도 보호범위8파일(world/layout/Main/project/전투설정/배경/기사·슬라임 PNG)의 SHA도 전후 동일하다.
