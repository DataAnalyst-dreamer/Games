# 쿼터뷰 배우·무기 미술 통일 패스

2026-09-14 · D-143 후속 · 부분 후보 비교 기능 실행 완료 / 핀·전체 세트 미완료

사용자 피드백: 조작·공간감·타격감은 좋아졌으나 검과 임시 기사·몬스터의 미술이 배경과 어울리지 않는다. 다음 개발의 병렬 진행을 승인했다.

## 이번 범위

핀의 승인 외형(은색 투구, 붉은 깃털, 황토 튜닉, 초록 망토, 오른손 검·왼손 방패)과 몸체 64×96 제작 목표, FHD 출력은 유지한다. 새 정지 자산의 실제 출력 크기를 제작 목표와 혼동하지 않는다. 검·슬라임·핀을 동일 배경에 배치해 밀도·색·크기를 비교하는 엔진 화면을 만든다.

| 병렬 담당 | 산출물 | 경계 |
|---|---|---|
| 아트 | 개별 생성 자산, 원본·프롬프트·출처, 투명도 검사 | 기존 자산 덮어쓰기·독립 포즈를 이어 붙인 가짜 보행 금지 |
| 런타임 | 별도 FHD 디자인 비교 화면과 자산 연결 | 정지 시안을 기본 플레이 모션으로 대체하지 않음 |
| QA | 실제 엔진 캡처·실행기·회귀 검사·독립 코드 검토 | 엔진 실행 담당 단일화, 기존 본편·세이브 보존 |
| 오케스트레이터 | 기준·교차 검토·직접 시각 검수·사용자 공유 | 기술 통과를 미술 완성으로 보고하지 않음 |

## 적용 게이트

1. 생성 원본의 실제 알파·잘림·장비 방향을 검사한다. 불투명 체크무늬는 투명 자산으로 적용하지 않는다.
2. 배경과 함께 FHD 표시 크기로 비교한다. 확대 원화가 좋아 보여도 게임 화면 판독이 나쁘면 후보로 남긴다.
3. 검의 손잡이·끝점·앞뒤 가림은 기존 전투 판정과 별도로 검증한다. 타격 준비 50ms / 활성 85ms / 회수 140ms와 현행 피해·이동 설정은 유지한다.
4. 새 핀의 걷기·공격 연속 프레임은 별도 완료 조건이다. 정지 비교 화면은 그 완료 증거가 아니다.
5. 중요한 외형·조작·시야 변경이 필요하면 해당 작업을 멈추고 묻는다. 승인 범위 내 새 시안·게임 캡처는 만들어지는 대로 공유한다.

본편 전체 쿼터뷰 이관, 경제·전직 수치 확정, 저장 이관은 이번 미술 통일 패스에 포함하지 않는다. 기존 콘텐츠 작업의 미완료 상태는 중앙 작업 관리표에 유지한다.

## 원본 직접 검토 메모

- 검 v1: 원본 뷰에서 회색 후광이 보였으나 담당 실측에서 해당 좌표는 알파 0이었다. 원본 뷰만으로 불투명 후광 결함을 확정하지 않고 엔진의 실제 알파 합성으로 판단한다.
- 슬라임 v1: 청록 젤리 재질과 얼굴 형태가 원본에서 읽힌다. 작은 표시 크기와 어두운 배경 검사는 별도다.
- 핀 정지 v1: 연결된 다리·오른손 검·왼손 방패는 읽히지만 장화가 커지고 비율이 길어졌다. 실제 불투명 체크 배경이 있어 이 원본은 투명 배우로 적용하지 않는다. 승인 외형의 새 최종본으로 간주하지 않는다.
- 핀 그림 속 짧고 넓은 검과 별도로 생성한 길고 곧은 검은 동일 도안이 아니다. 색감 비교 후보이며 완성된 동일 장비 세트라는 표현을 사용하지 않는다.

위 메모는 원본 정지 그림의 한정 관찰이다. 걷기·공격 프레임 완성이나 새 캐릭터의 플레이 적용을 뜻하지 않는다.

핀 배경 추출 v2도 불투명 RGB 체크 배경을 유지했고 얼굴·질감을 재해석했다. 오케스트레이터가 원본을 직접 확인하여 추가 반복 생성을 중단했다. [생성 4회와 원본/프롬프트/알파 기록](../art/preview/quarter-view/unified-v1/README.md)을 보존한다. 최종 비교 기능의 범위는 **검·슬라임 두 후보 + 핀 적용 보류 상태**로 제한한다. 세 자산 완비 게이트는 통과하지 못했으며, 앱 동작 검증과 구분한다.

첫 엔진 캡처 4장(`quarter-view-design-check-92124a9197a7406f82e4a20e9a384827`)을 루트와 별도 표시 검토자가 확인했다. 마을·어두운 판·밝은 판에서 원본 뷰의 넓은 검 후광은 나타나지 않았다. 1배 슬라임 얼굴/외곽은 구분되나 세부 젤리 재질과 검 손잡이 감김은 축약된다. 슬라임은 접지 그림자가 없어 지면 접촉 표현이 다음 과제다. 당시 핀 ‘준비 중’ 문구는 최종 보류 상태 수정 전의 역사 화면이며 최종 UI 검증과 구분한다.

## 실행 결과와 인계

상세 로그·원본 크기·최종 준비본 해시는 [실행 검수 보고서](../qa/quarter-view-design-comparison-20260914.md)에 기록했다.

- `prototypes/quarter-view-lab/Compare-Design.cmd`: 별도 정지 비교. Tab으로 나란히/기존/후보, Z로 1배/2배, B로 마을/어두운 판/밝은 판, Esc 종료. 새 핀은 빈 슬롯과 실패 상태로 남긴다.
- 기존 `Play-Quarter-View.cmd`는 기존 이동·타격·대역 자산을 유지한다. 새 정지 그림을 모션으로 사용하지 않는다.
- 최종 동일 소스의 정상 import, Main 11, 전투 58, GUI 19, 공격 연속 캡처 12, 손 결합 격자 18, **부분 비교 앱 24** 검사 모두 자연 종료/native 0. 루트가 결과 로그와 별도 VerifyOnly exit 0을 확인했다.
- 최종 비교 캡처는 `quarter-view-design-check-c61646f4a45e454cbd03ecf2bc8443d7` 아래 FHD 4장이다. 루트가 최종 나란히/후보2배 화면을 직접 검토하여 핀 보류 문구와 배치를 확인했다.
- 최초 세 자산 완비 검사는 19 PASS / 3 FAIL / native 1로 보존했다. 최종 `ready.design_comparison.asset_set_ready=false`, `available_candidates=2`, `required_candidates=3`, `fin_animation_ready=false`를 유지한다. 부분 앱 통과는 실패한 핀을 성공으로 바꾼 것이 아니다.
- 런처 초안의 잘못된 검사 분기 연결은 루트가 발견하고 담당이 수정한 뒤 독립 코드 검토를 거쳤다. 수정 이전 초안으로 최종 ready를 만들지 않았다.

다음 우선순위는 승인 핀의 형태와 투명 배경을 함께 보존하는 제작 경로 확보, 검 도안 통일, 슬라임 접지/실제 연속 모션이다. 이번에는 추가 계정·외부 서비스·비용·정식 본편 이관을 수행하지 않았다.
