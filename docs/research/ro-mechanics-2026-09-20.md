## 1. 6스탯과 파생치

RO는 **STR / AGI / VIT / INT / DEX / LUK** 6스탯. 우리 GDD는 **STR / DEX / INT / VIT / LUK** 5스탯으로 AGI가 없다.

| RO 스탯 | 주 효과 | 부가 효과(파생치) |
|---|---|---|
| STR | 물리 ATK(무기 데미지 가산) | 소지 중량 한도 |
| AGI | **회피(FLEE)**, **ASPD(공격 속도)** | 일부 상태이상 저항 |
| VIT | HP 최대치, **소프트 DEF**(물리 피해 감소) | 상태이상 내성, HP 회복력 |
| INT | MATK(마법 데미지), SP 최대치·회복 | **가변 캐스팅 시간 감소**, MDEF 일부 |
| DEX | **HIT(명중)**, ASPD(무기별 보정), 가변 캐스팅 시간 감소(INT 절반 가중) | 원거리 물리 데미지, 캐스팅 실패(시전 중 피격 캔슬) 확률 감소 |
| LUK | 크리티컬 확률, 약간의 HIT/FLEE/모든 스탯 소폭 | 상태이상 내성·유발률, 카드/아이템 드랍 보정(서버별로 편차 있음, 기본 드랍률 자체와는 별개) |

파생치 수식(공식·iRO 계열 위키 요약, Renewal 기준):
- `MATK ≈ INT + floor(INT/5)^2` ~ `INT + floor(INT/7)^2` 구간(장비 MATK 별도 가산)
- `HIT = 175 + BaseLv + DEX + floor(LUK/3) + 보너스`
- `FLEE = 100 + BaseLv + AGI + floor(LUK/5) + 보너스`
- `SoftDEF = floor(VIT/2 + AGI/5 + BaseLv/2)`, `HardDEF`는 장비 기반, 최종 피해는 `dmg * (4000+HardDEF)/(4000+HardDEF*10)` 형태의 체감 감소 곡선(예: HardDEF 275 ≈ 피해 1/3 감소, 500 ≈ 절반 감소)
- `SoftMDEF = floor(INT + VIT/5 + DEX/5 + BaseLv/4)`
- `CRIT = floor(LUK*0.3) + 1` (%)
- `ASPD`는 클래스·무기 종류·AGI·DEX·상태이상속도버프의 복합 함수, 상한 190(3차 전 클래스)/193(3차 클래스)
- **가변 캐스팅 시간**: `VCT = BaseVCT * (1 - sqrt((DEX*2+INT)/530)) * (기어감소) * (스킬감소)` — DEX가 INT의 2배 가중치로 캐스팅을 줄인다. `DEX*2+INT ≥ 530`이면 가변 캐스팅 0 수렴.

### AGI 도입 시 DEX와의 역할 분담 제안
RO의 실제 분업은 **"AGI=몸(회피·속도), DEX=조준(명중·시전단축)"**으로 갈라져 있다. 우리 게임에 AGI를 추가한다면:
- **AGI**: 이동속도/구르기 쿨다운 또는 회피 판정(현재 GDD에 명시적 "회피 스탯"이 없음), 공격 속도(ASPD 역할)
- **DEX**: 명중률·크리티컬 발생 조건(원거리 명중 보정), 스킬 캐스팅 시간 단축 — **현재 GDD의 "공격 속도" 효과를 DEX에서 떼어 AGI로 옮기고, DEX는 명중/원거리 데미지/캐스팅 단축에 집중**시키는 안이 RO식 역할 분리와 맞는다.
- 다만 우리는 실시간 액션(RO는 명중률 판정 기반 MMORPG)이라 "HIT/FLEE 확률 판정"을 그대로 가져오면 조작감이 나빠진다(회피 성공 여부가 스탯 굴림이 아니라 플레이어의 구르기 타이밍이어야 함). **RO의 HIT/FLEE 개념은 "명중 실패로 데미지 0"이 아니라 "크리티컬 방지선/치명타 상한" 같은 보조 수치로 완곡화해 도입**할 것을 권장.

## 2. 스탯 포인트 비용 곡선

- 공식(iRO 계열 다수 위키 일치): **스탯을 X→X+1로 올리는 비용 = `floor((X-1)/10) + 2`**
  - 1~9: 포인트당 2 소모, 10~19: 3, 20~29: 4 … 10 구간마다 +1
  - 1→99까지 총 628포인트 소요(제곱형에 가까운 체감 난이도 상승, 완만한 2차 곡선)
- 레벨당 지급: **베이스 레벨업 시 스탯 포인트 지급**(레벨이 오를수록 지급량도 완만히 증가하는 표, 정확한 레벨별 표는 미확인 — 소스 접근 차단). 저레벨 노비스는 약 48포인트 내외로 시작 스탯 배분(전직 전 1차 성장 구간), 초기 캐릭터는 전 스탯 1로 시작.
- 시사점: **"낮은 스탯 초반엔 싸게, 몰빵할수록 비싸게"**가 핵심 원리. 우리 `stats.json`은 현재 스탯당 계수가 **선형**(`STR*0.2`, `INT*0.15` 등)이고 포인트 비용도 고정 1:1이라, "몰빵 억제" 장치가 없다. RO식 체증 비용 곡선을 도입하면 GDD 5.3의 "사제 전체 리셋(레벨×100G)"과도 자연스럽게 맞물린다(비싸진 뒷부분 포인트를 리셋으로 재분배하는 유인).

## 3. 직업 레벨과 스킬 포인트

- **베이스 레벨(BaseLv)**: 전투력 전반, 스탯 포인트 지급의 기준.
- **잡 레벨(JobLv)**: 클래스 숙련도, **스킬 포인트 지급의 기준**. 1잡레벨당 스킬 포인트 1점 지급.
- 잡 레벨 상한: 노비스(기본 전직 전) 10 → 1차 전직, 1차 클래스 상한 50(일부 클래스 70), 1차 잡레벨 40 이상이면 2차 전직 가능, 2차도 상한 50 부근. 즉 **"레벨 캡 = 다음 전직 게이트"** 구조.
- **전직 스킬 트리**: 선행 스킬(특정 스킬 N레벨 이상 습득)과 요구 잡레벨을 함께 게이팅. 1차 클래스 스킬 트리 규모는 대략 **9~10개 내외**(액티브 공격기 2~3, 버프/자기강화 1~2, 패시브 숙련도 2~3, 유틸/생존기 2~3 비율 — 예: 검사 계열은 무기 숙련 패시브 2종 + 회복량 증가 패시브 + 공격 스킬(단일/범위 각 1) + 도발형 유틸 + 생존 패시브(피격 중 행동 유지) + 저HP 자동발동형 버프로 구성).
- **스킬 레벨 1~10**: 스킬 1개가 레벨 10까지 성장, 레벨이 오르면 **데미지/타수/지속시간 등 효과가 커지고 SP 소모·캐스팅시간·후딜레이도 함께 늘어나는 트레이드오프**(예: 공격 스킬 SP 소모가 `기본값 + 레벨*2`형 선형 증가).
- 액티브/패시브/버프 비율: 1차 클래스 기준 대략 **액티브(공격/유틸) 40~50% : 패시브(숙련도·상시효과) 30% : 버프·생존기 20~30%**.

### 우리 프로젝트 적용 제안
- 현재 `stats.json`에 `skill_points_per_levelup: 1`이 이미 정의되어 있음(레벨업당 1). RO의 "베이스/잡 레벨 분리" 자체는 오픈월드 단일 레벨 구조인 우리 게임엔 과할 수 있으나, **"스킬 포인트는 전투 숙련(사냥/퀘스트)으로, 스탯 포인트는 레벨업으로"** 식의 자원 분리는 파밍 루프 강화에 유효 — 예: 스킬 포인트 일부를 몬스터 도감 완성 보너스(GDD 5.3)에서도 지급.
- 스킬 레벨 1~10 대신, 액션 RPG 템포에 맞춰 **스킬당 3~5단계**(RO보다 짧게)로 압축하고, 레벨업마다 "데미지↑ / 후딜↓ / 스태미나·쿨다운↓" 중 하나씩 선택 강화하는 형태를 권장.

## 4. SP 자원 (우리의 스태미나와 병행 제안)

- SP 회복(기본): **가만히 서있을 때 4초, 앉아있을 때(sit) 8초마다 1틱 회복**(수치는 정반대로 보도되는 자료도 있어 서버·버전차 존재 — 핵심은 "정지 상태일수록 빠르게 회복"이라는 원칙만 확실), 회복량은 `기본 1 + (Max SP/100) + (INT/6)`형 가산식, INT가 높을수록 SP 회복도 빨라짐.
- **Increase SP Recovery류 패시브/스킬**로 초당 회복량 자체를 %/고정치로 강화 가능(레벨당 +8%p, 최대 +80%까지 등 예시 확인).
- SP는 "액티브 스킬 전용 자원"이고, 우리 스태미나는 "구르기/가드 전용 자원"이라는 점에서 **자원 종류가 이미 분리**되어 있음. 병행 도입 시 역할 분담 제안:
  - **스태미나**: 회피(구르기)·가드 등 "방어/기동" 행동 전용 (현행 유지)
  - **SP(신규, 스킬 전용)**: 액티브 스킬(투사체·범위기·버프) 발동 자원. **정지 중 자동 회복 + 전투 중에도 완전히 멈추지는 않되 느리게(예: 전투 중 회복속도 30~50%)** 방식을 권장(RO는 전투 중이라도 회복은 되고 "앉기"로 가속하는 방식 — 우리는 실시간 액션이라 "앉기" 대신 "비전투 유지 시간"으로 대체 가능).
  - 두 자원을 겹치지 않게 하면 "회피형 플레이(스태미나 소모)"와 "스킬 캐스터형 플레이(SP 소모)"가 자연히 분리되어 빌드 다양성에 기여.

## 5. 단축바(핫키)

- 기본 단위: **한 줄에 9칸(F1~F9에 대응)**. 기본으로 최대 3줄(F12로 순환 전환, 총 27칸)까지 구성 가능했고, 이후 UI 개편으로 여러 줄을 동시에 화면에 배치 가능해짐(최대 4줄 동시 표시라는 자료도 있음, 세부 버전차는 미확인).
- 등록 방식: **드래그&드롭**으로 스킬창/인벤토리에서 슬롯에 끌어놓기. 스킬과 아이템(포션 등)을 **같은 종류의 슬롯에 혼용** 등록 가능.
- "배틀모드"처럼 QWERTY 등 알파벳 키열 전체를 두 번째·세 번째 줄에 매핑해 27칸을 동시에 쓰는 상급 설정도 존재(대부분의 유저는 1줄만 사용).

### 키보드 액션 RPG로 축약할 때 권장
- **1~9 한 줄(9칸)을 기본 단축바로 고정**, 필요 시 마우스 사이드버튼이나 보조키(Shift+숫자)로 세컨더리 9칸을 추가하는 2단 구성이면 RO의 "27칸 중 실제로는 1줄만 씀" 실사용 패턴과 맞고 학습 부담도 낮다.
- 아이템(포션 등)은 **전용 소모품 슬롯(예: 상하 화살표 키 또는 별도 줄)**으로 분리하는 편이, 실시간 전투 중 오조작(스킬 대신 포션 소모) 리스크를 줄인다 — RO는 턴 여유가 있는 판정형 전투라 혼용이 문제없지만, 우리는 프레임 단위 액션이라 분리가 안전.
- 드래그 등록은 마우스/게임패드 UX엔 좋으나, **키보드 전용 플레이엔 "스킬 트리 화면에서 숫자키 직접 지정" 방식**을 병행 지원할 것.

## 6. 퀘스트 보상 표시 관행

- (미확인) — 차단된 위키(iRO Wiki Quests, ragnarok.fandom Quests 카테고리, RateMyServer 퀘스트 DB) 원문을 직접 열람하지 못해 "수락 전 보상 미리보기 UI"의 정확한 화면 구성은 확인하지 못함.
- 검색 요약으로 확인되는 범위: RO의 반복 사냥 퀘스트(특정 몬스터 N마리 처치/납품형)는 **완료 시 베이스 EXP + 잡 EXP를 함께 지급**하는 것이 일반적이며, 커뮤니티 위키(TalonRO 등 사설 서버 위키)들이 "이 퀘스트가 주는 경험치/아이템" 표를 별도로 정리해 제공할 정도로 **원 게임 UI 내 사전 고지가 충분치 않았다는 방증**(그래서 팬 위키가 표로 보완).
- 업계 일반 관행(RO 한정 아님, 참고용): 퀘스트 수락 창에 **보상 아이콘 나열(경험치 막대/골드 숫자/아이템 아이콘 + 수량)**을 배치하고, 완료 시 동일한 레이아웃의 팝업으로 "획득 완료" 표시하는 것이 표준.

### 권장 (일반 관행 기반, RO 자체 사양 확인 불가로 업계 표준으로 대체)
- 수락 전: 퀘스트 창에 **EXP(막대 미리보기 또는 숫자), 골드, 아이템 아이콘×수량**을 고정 레이아웃으로 노출.
- 완료 시: 동일 레이아웃 + "레벨업/도감 갱신" 등 파생 효과를 함께 표시(우리 GDD 5.3의 도감 보너스와 연결하기 좋음).

## 7. 스킬 이펙트 관행

- RO 자체의 정밀한 프레임 데이터는 미확인(사설 서버 포럼 스니펫 수준). 다만 **RO가 정의한 3단계 딜레이 구조**는 명확히 확인됨:
  1. **애니메이션 딜레이(Animation Delay)**: 시전/공격 모션이 끝날 때까지 다른 스킬 불가 — 즉 **"모션 정지"가 이 구간**.
  2. **애프터캐스트 딜레이(After Cast Delay)**: 스킬 고유의 후딜레이. 감소 효과가 있어도 **하한선(약 300ms, 초당 최대 3스킬)**이 있어 무한 단축을 막음.
  3. **쿨다운(재사용 대기시간)**: 애프터캐스트 딜레이와 동시에 시작, 애프터캐스트만 끝나면 다른 스킬은 바로 쓸 수 있고 같은 스킬만 쿨다운 대기.
- 일반 액션 게임 이펙트 설계 원칙(업계 공통, RO 한정 아님):
  - **임팩트 프레임을 판정/데미지 발생 시점과 정확히 동기화**하고, 후속 잔여 모션(팔로우스루)은 데미지 판정과 분리해 "느낌"만 담당하게 한다.
  - 타격 시 수 프레임의 **히트스톱(짧은 정지/슬로우)**을 넣으면 데미지 수치를 바꾸지 않고도 타격감이 크게 상승.
  - 이펙트는 **발동 지점(시전자 손/무기 끝, 또는 타겟 중심)에 앵커**시켜 좌표가 붕 뜨지 않게 하고, 이펙트 지속시간은 **200~500ms 범위(짧은 즉발기)~800ms~1.2s(대형 캐스팅기)**가 어색하지 않은 체감 구간(업계 일반 가이드 기준, RO 고유 수치 아님).
  - 회피/가드로 캔슬 가능한 지점을 애니메이션 상태머신에 명시적으로 정의(모션 중간에 "캔슬 윈도우" 프레임 태그)해야 조작감이 끊기지 않는다.

## 패턴 (사례 공통 구조)

1. **자원 이원화**: 이동/생존형 자원(스태미나류)과 스킬 발동형 자원(SP류)을 분리하면 빌드 다양성이 자연히 생긴다.
2. **체증 비용**: 스탯이든 스킬이든 "더 올릴수록 더 비싸지는" 곡선이 몰빵 억제와 리스펙 동기를 동시에 만든다.
3. **이중 게이트(레벨×숙련도)**: 캐릭터 레벨(힘의 총량)과 클래스/스킬 숙련도(선택의 폭)를 분리하면, "강하지만 아직 배울 게 남은" 상태를 오래 유지할 수 있다.
4. **딜레이 3분할(모션/후딜/쿨다운)**: 하나의 "쿨타임" 대신 최소 2개 층(모션 잠금 vs 재사용 대기)으로 나누면 콤보 설계와 밸런스 조정이 독립적으로 가능해진다.
5. **핫키는 실제로 1줄만 쓴다**: 시스템이 27칸을 지원해도 실사용은 9칸 내외 — 확장성보다 기본 1줄의 완성도가 중요.

## 주의점

- **저작권/표절**: 스킬 이름·아이콘 디자인·직업명·대사·클래스 트리 구조를 그대로 베끼지 말 것. 이 문서의 예시 스킬명(배쉬, 프로보크, 마그넘 브레이크 등)은 공개된 게임 메커니즘 설명을 위한 최소 인용이며, 우리 게임에는 **수식·비율·딜레이 구조만** 가져오고 이름·연출은 새로 만들어야 한다.
- **수치 그대로 이식 금지**: `floor((X-1)/10)+2` 같은 공식은 "체증 곡선의 형태" 참고용이지, 우리 만렙(50)·스탯 캡(`max_per_stat: null`) 구조에 그대로 넣으면 총 포인트 예산이 안 맞을 수 있다. 계수는 우리 `stats.json`의 `_balance_todo` 프로세스로 재산정해야 한다.
- **북유럽 신화 명칭 차용 주의**: "라그나로크"라는 제목 자체가 북유럽 신화 공유 유산에서 왔듯, 우리도 신화적 명칭을 쓸 수 있으나 특정 살아있는 신앙 공동체의 성물/의례를 희화화하지 않도록(이슬란드 세계관은 가상의 섬나라이므로 리스크는 낮으나, 스킬명에 실제 북유럽 신 이름을 붙일 경우 시각 연출이 특정 종교적 상징을 조롱하는 톤이 되지 않게 주의).
- **판정형 vs 실시간 액션의 근본 차이**: RO의 HIT/FLEE(확률 판정으로 데미지 0/부여) 시스템을 액션 게임에 그대로 이식하면 "맞았는데 데미지가 0"이라는 조작감 배신이 생긴다. 확률 판정은 크리티컬/상태이상 발생 같은 보조 요소로만 쓰고, 회피 자체는 플레이어 조작(구르기 타이밍)으로 남겨야 한다.
- **미확인 항목 재검증 필요**: 6번(퀘스트 보상 UI)과 SP 회복의 정확한 초 단위(4초/8초 vs 반대) 등은 이번 세션에서 1차 출처를 직접 열람하지 못했다. 스펙 확정 전 `irowiki.org`/`ratemyserver.net` 접근이 가능한 환경에서 재확인 권장.

|---|---|---|
| 스탯 비용 곡선 | `cost(n→n+1) = floor(n/10) + 1` (RO의 `floor((X-1)/10)+2`를 만렙 50 규모로 축소한 근사형, 1~9=1p, 10~19=2p …) | §2 |
| AGI 추가 시 역할 | AGI=이동속도·공격속도(ASPD 역할), DEX=명중·원거리데미지·캐스팅단축(현 GDD의 "공격속도"를 DEX→AGI로 이관) | §1 |
| 스킬 자원 | 신규 SP 자원, 회복식 `regen/tick = 1 + INT*0.05`, 비전투 중 tick 2~3초, 전투 중 tick 4~6초(RO 전투/비전투 회복 차등 원칙만 차용) | §3, §4 |
| 스킬 레벨 | 스킬당 3~5단계(RO의 10단계보다 축약), 레벨마다 데미지↑ + SP소모 소폭↑ | §3 |
| 딜레이 구조 | 모션 잠금(공격 애니메이션 길이) / 후딜(스킬 고유, 하한 150~250ms) / 재사용 대기(쿨다운) 3계층 분리 | §7 |
| 핫키바 | 기본 1~9 한 줄(스킬), 별도 소모품 전용 슬롯 3~4칸(포션 등, 숫자키와 분리) | §5 |
| 이펙트 지속시간 | 즉발기 200~500ms, 캐스팅형 800ms~1.2s, 타격 프레임에 3~5프레임 히트스톱 | §7 |
| 퀘스트 보상 UI | 수락 전/완료 시 동일 레이아웃으로 EXP·골드·아이템 아이콘 고정 노출(업계 표준, RO 자체 UI 미확인) | §6 |
