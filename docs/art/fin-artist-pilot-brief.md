# 핀 정면 보행 — 외부 픽셀 아티스트 파일럿 의뢰 브리프

2026-09-13 · **미전송 로컬 초안 / 견적 요청 문안 후보**. 협업 경로 검토용이며 발주·계약·결제·일정·제작 착수 승인이 아니다. 수신자·예산·마감일은 미정이다.

## 1. 의뢰 목적

탑다운 2D 직접조작 액션 RPG 《이슬란드 연대기》의 주인공 핀을 실제 게임용 픽셀 캐릭터로 정리하고, 정면 보행의 품질을 먼저 확인하고자 합니다. 작은 캐릭터의 외형 매력과 접지·체중 이동을 함께 살리는 작업입니다. 첫 파일럿은 **정면 1루프**이며 다른 방향·전투 모션은 후속 견적입니다.

크루세이더 퀘스트는 SD 픽셀 표현력의 참고입니다. 원작 캐릭터·장비·스프라이트를 복제하거나 추출하는 요청이 아닙니다. 젤다식 자유로운 탐험 방향이지만 이번 의뢰에 게임 시스템 제작은 포함하지 않습니다.

## 2. 확정 조건과 협의할 규격

| 항목 | 상태 / 요청 |
|---|---|
| 인물 | 핀, 귀여운 견습 기사. 기존 승인 외형 유지 |
| 외형 | 은색 열린 투구, 붉은 깃털, 갈색 앞머리, 황토색 튜닉, 초록 망토, 갈색 부츠 |
| 장비 | **캐릭터 본인 오른손 검 / 왼손 방패**. 정면에서 화면 왼쪽 검, 화면 오른쪽 방패 |
| 몸체 예산 | **64×96** 기준. 장비·깃털의 실제 여백은 기준 이미지와 함께 합의하며 전체 파일 폭을 강제로64로 자르지 않음 |
| 게임 표시 | **FHD 1920×1080**. 첫 검토는 정수2배 표시 후보이나 최종 카메라 줌 확정 아님 |
| 셀·피벗 | **96×128 셀, (48,112) 발 기준점은 미확정 작업안**. 실제 보폭·장비 여백 검토 후 합의 |
| 프레임·속도 | 정면 보행8프레임 목표, 첫 재생8fps는 시험값. 실행 이동 속도와 맞춰 조율 |
| 스타일 | 네이티브 픽셀 단위의 선명한 형태·일관된 팔레트. 무리한 색수 축소·스무딩 금지. 색수는 아직 고정하지 않음 |

64×96은 몸체 제작 기준이고, 기존 `front-64.png`는 장비 포함66×96입니다. 기존 소형 그림의 손상된 픽셀을 그대로 보존하라는 의미는 아닙니다. 얼굴·투구·장비 디자인을 바꾸지 않는 범위의 픽셀 정리와 실루엣 개선은 파일럿에서 제안해 주세요. 정체성 변경은 먼저 확인이 필요합니다.

## 3. 제공 예정 참고 파일

외부 전달 전 사용자가 전달 범위를 승인해야 합니다. 저장소 전체를 보내지 않고 아래 선택 자료만 묶습니다.

- `docs/art/preview/fin-resolution/front-64-source.png`: 승인 외형의 고해상도 기준. **AI 생성 참고 이미지**이며 레이어 원본이 아닙니다.
- `docs/art/preview/fin-resolution/front-64.png`: 소형 표시 후보. 완성 애니메이션 원본 아님.
- `docs/art/preview/fin-cq-concept-v1.png`: 초기 외형 분위기 참고. 이미지 내 배경·영문 문구까지 제작 요청하는 것은 아님.
- `docs/art/fin-64-production-spec.md`: 규격/포즈 요구.
- 실패 사례는 필요 시 별도 제공: 다리 분할·압축 블록아웃 및 독립 생성 보행 시트. **재사용용이 아니라 피해야 할 결과 설명**입니다.

현재 승인 핀의 편집 가능한 레이어/타임라인 원본은 없습니다. 제공 AI 이미지의 출처를 숨기지 않으며, 이를 참고한 작업을 맡을 수 있는지도 견적 회신에서 확인합니다.

## 4. 단계별 범위와 중간 검수

| 단계 | 요청 산출물 | 다음 단계 조건 |
|---|---|---|
| P0 | 정면 기준 포즈 픽셀 정리, 팔레트·셀·피벗 제안 | 승인 외형과 실제 표시 크기 검토. 재디자인이 필요하면 중지·확인 |
| P1 | **접지A·통과A·접지B·통과B 전신 키포즈4개** | 골반→허벅지→무릎→발목 연결, 접지, 장비 손, 동일성 확인 |
| P2 | 키포즈 사이 중간 그림을 더한 **정면 보행8프레임 1루프** | 7→0 연결, 정지→보행→정지, 몸의 이동과 발의 상대 움직임 검수 |
| P3 | 실제 FHD 배경 위 엔진 재생과 수정 | 플레이 화면의 가독성·미끄러짐·잘림·피벗 검수. 기술 재생과 시각 승인을 구분 |
| 후속 별도 | 좌·우·후면 보행 및 방향 전환, 이후 공격·가드·회피 등 | 정면 파일럿 통과 후 범위·금액·일정 별도 승인 |

엔진 통합과 녹화는 프로젝트 측, 프레임 그림과 편집 원본은 아티스트 측을 기본 협업안으로 제안합니다. 기술 수정이 아티스트 범위에 포함되는지는 견적에 구분해 주세요. 이 브리프의 검수 단계는 아직 계약상 지급 조건이 아닙니다.

## 5. 프레임 품질 기준

- 각 포즈는 온전한 전신 그림으로 설계합니다. 다리만 잘라 길이를 줄이거나 직사각형으로 엉덩이 틈을 메운 방식은 사용하지 않습니다. 공통 얼굴·투구 픽셀 재사용 자체는 가능하지만 관절과 가림은 포즈에 맞춰 직접 해결해야 합니다.
- 셀의 기준점은 프레임 사이 고정합니다. **모든 프레임의 가장 아래 픽셀을 바닥에 강제 맞추라는 뜻은 아닙니다.** 지지 발과 공중 발의 높이는 달라야 합니다. 인플레이스 루프의 지지 발 상대 이동은 엔진의 전진 속도와 함께 검토합니다.
- 미끄러짐 검수에서는 캐릭터 원점의 월드 전진과 스프라이트 내 지지 발의 반대 방향 이동을 합쳐, 접지 구간에 지면 위 발이 불필요하게 미끄러지는지 봅니다. 원점 고정이 곧 발의 화면 좌표 고정을 뜻하지 않습니다. 의도한 접지/공중 구간을 프레임별로 표기해 주세요.
- 접지 A는 본인 왼발(정면 화면 오른쪽) 전진 접지, 통과 A는 반대 다리가 몸 아래를 통과합니다. 접지 B·통과 B는 반주기입니다. 앞/뒤 다리의 가림 순서와 튜닉 밑단, 부츠 뒤꿈치/발끝이 자연스럽게 연결되어야 합니다.
- 머리·눈·투구·방패 크기와 부츠 구조가 매 프레임 달라지면 안 됩니다. 의도된 작은 상하 체중 이동은 가능하지만 무작위 좌우 흔들림·프레임별 확대축소는 불가합니다.
- 검·방패·팔·망토는 걸음에 따른 작고 일관된 지연과 반대 움직임을 갖습니다. 검이 공격처럼 크게 휘둘러지지 않아야 합니다.
- 좌우 방향은 단순 전체 미러로 완성 처리하지 않습니다. 본인 오른손 검/왼손 방패를 유지하도록 손·장비·몸 뒤 가림을 다시 구성해야 합니다. 이 항목은 후속 방향별 견적에 반영해 주세요.
- 실제 RGBA 투명 배경, 체크무늬가 칠해진 배경 금지. 마젠타/흰 테두리·부츠 잘림·장비 셀 넘침을 밝고 어두운 배경에서 검사합니다.

## 6. 파일럿 납품물 요청안

- 편집 원본: `.aseprite` 또는 사전 합의한 동등 포맷. 레이어·셀·타임라인·프레임 시간이 유지되어야 합니다. 호환 툴/버전을 함께 표기해 주세요.
- 레이어 구분: 몸체/머리, 검, 방패, 망토 등 필요한 요소를 편집 가능한 구조로 관리. 레이어 수 자체보다 프레임 수정 가능성을 우선합니다. 앞뒤 가림용 레이어 재배치가 가능해야 합니다.
- 태그: 예시 `idle_down_reference`, `walk_down` 및 키포즈 식별. 파일럿에 없는 방향/공격 태그를 완성으로 표시하지 않습니다.
- PNG: 정면 기준 포즈, 개별 프레임, 투명 스프라이트 시트. 정수 좌표·고정 셀·일관된 여백, 자동 타이트 트리밍은 기본 비활성 요청입니다.
- JSON: 프레임 순서/사각형/지속시간, 태그 범위, 셀 크기, 피벗 좌표와 원점 규약, 제작 버전. 엔진 측과 샘플 스키마를 사전 합의합니다.
- GIF 또는 영상: 루프 확인용. **GIF는 투명도/색 정본이 아니며 PNG와 편집 원본이 기준**입니다.
- 간단한 변경 기록·팔레트·사용 폰트/외부 자료/도구 목록. PNG 한 장을 `.aseprite`에 넣은 포장 파일은 프레임 편집 원본 납품으로 보지 않습니다.

포맷 근거: Aseprite 공식 문서는 원본에 레이어·프레임·팔레트·태그·슬라이스를 보존하며, 게임용 결과와 원본을 구분하도록 안내합니다. CLI의 PNG 시트·JSON 내보내기도 공식 지원됩니다. 이는 우리 환경에 편집기가 설치되어 있다는 뜻은 아닙니다. [원본 파일 안내](https://www.aseprite.org/docs/files/) · [PNG/JSON 내보내기](https://www.aseprite.org/docs/cli/)

## 7. 권한·공개 범위 협의 질문

아래는 **계약 전 확인 질문**이며 법률 판단이나 이미 확보한 권한이 아닙니다.

1. 상업 게임 배포, 홍보 화면·영상, 향후 플랫폼 이식에 사용할 수 있는가?
2. 프로젝트 담당자와 후속 아티스트가 수정·재편집·추가 모션을 제작할 수 있는가?
3. **공개 GitHub에 PNG와 편집 원본까지 올리고 복제/포크로 재배포되는 범위**를 허용하는가? 게임에 포함한 배포 권한과 별개로 명시해야 합니다. 불가하다면 원본 비공개 보관 등 저장소 정책을 사용자와 먼저 결정합니다. 허가 없이 업로드하지 않습니다.
4. 독점/비독점, 저작자 표기 방식, 아티스트 포트폴리오 공개 시점·범위, 수정본 권한을 어떻게 정할 것인가?
5. 제3자 자료를 사용한다면 출처·허용 범위와 재배포 조건을 제공할 수 있는가? 다른 게임 립이나 출처 불명 스프라이트 사용은 불가합니다.

공개 저장소의 열람·포크와 별도의 이용허락은 구분해야 합니다. 아래는 협의 시 확인할 플랫폼 안내이며, 아티스트 저작물의 상업 이용/원본 공개 허가를 대신하지 않습니다. [GitHub 저장소 라이선스 안내](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/licensing-a-repository)

## 8. 사람 작업·AI 사용 정책 제안 — 아직 미승인

권고안은 **기존 AI 시안은 외형 참고로 공개하고, 최종 키포즈·중간 프레임의 픽셀 설계와 검수는 사람이 책임지는 방식**입니다. 독립 생성 프레임 연결이나 생성 그림을 수작업으로 오표시하는 납품은 피합니다. AI 사용을 전면 금지할지, 보조 도구 사용을 사전 신고 조건으로 허용할지는 사용자가 결정해야 합니다. 아티스트는 사용 단계·도구·작업 원본 제공 범위를 미리 설명해 주세요. 이 문구를 미승인 상태에서 확정 계약 조건처럼 전송하지 않습니다.

## 9. 견적·일정 회신 요청

- P0/P1/P2/P3별 비용, 포함 산출물, 착수·완료 예상 시점과 필요한 입력 자료.
- 단계별 포함 수정 횟수, 피드백 왕복/응답 기준, 범위 변경과 납품 오류 보정의 구분, 추가 수정 비용.
- 4방향 확장·전투 모션의 별도 견적 방식. 첫 파일럿 비용과 혼합하지 않기.
- 편집 원본·상업 이용·수정권·공개 저장소 재배포 허용이 가격에 각각 포함되는지.
- 중단/취소 시 중간 산출물과 지급 범위, 결제 방법·수수료·세금 표시 방식.
- 같은 정도 크기의 **실제 보행 루프와 픽셀 편집 원본 구조**를 확인할 수 있는 포트폴리오. 화려한 정지 일러스트만으로 모션 품질을 판단하지 않기.

현재 예산·가격·소요기간·수정 횟수를 임의 확정하지 않았습니다. 무료 테스트 작업을 요구하는 요청도 아닙니다. 파일럿 자체가 유상인지와 지급 조건은 정식 의뢰 전에 합의해야 합니다.
