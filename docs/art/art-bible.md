# 아트 바이블 (초안) — 《이슬란드 연대기》

> 기준 문서: `docs/GDD-도트액션RPG-기획안.md` 9장(아트 디렉션). 이 문서는 9장의 표를 실제 작업
> 규칙(수치·hex·네이밍)으로 구체화한 것이며, M1 프로토타입 기간에는 `docs/art/asset-sources.md`

> 출시 버전은 이 문서 기준으로 원작 도트로 전량 교체한다.

톤 한 줄 요약: **아기자기하고 따뜻하다.** 무섭거나 그로테스크한 실루엣은 이 게임에 없다 — 몬스터도
"귀여운데 약간 능청스러운" 선을 넘지 않는다.

## 1. 해상도 · 비율 (GDD 9장)

| 항목 | 스펙 |
|---|---|
| 내부 렌더 해상도 | 640×360 (정수배 스케일, 1920×1080 = 3배) |
| 타일 크기 | 32×32px |
| 캐릭터 크기 | 32×48px, **2.5등신 SD** |
| 팔레트 | 지역당 32색 내외 제한 |
| 애니메이션 | 이동 6f · 공격 4~6f · 유휴 4f(개성 동작 필수) |

- 텍스처 필터는 항상 **Nearest**(픽셀 선명도 유지, 임포트 설정에서 필터/밉맵 끔).
- 2.5등신 = 머리가 몸 전체 높이의 약 40%를 차지하는 SD 비율. 팔다리는 짧고 둥글게, 손발은 뭉툭하게
  단순화한다 — Ninja Adventure Knight/Boy류의 헬멧-어깨-다리 3블록 구성을 기준 실루엣으로 삼는다
  (`docs/art/preview/knight_spritesheet_grid.png` 참고).
- 32×48 캐릭터 셀 안에서 발밑(피벗)은 셀 하단에서 위로 약 4~6px 지점(그림자가 깔리는 라인)에 둔다 —
  현재 M1 플레이스홀더(16px 소스, 발밑 -4px 오프셋)의 비율 감각을 그대로 32×48로 스케일한다.

### 1.1 M1 프로토타입 밀도 예외

M1~M2는 16×16 Ninja Adventure 소스를 **카메라 줌 2×**로 사용해 32px 그리드에 맞춘다(정수배 확대,
셰이더 확대 아님). 한 씬 안에서 16px 계열과 32px 계열을 섞지 않는다. 원작 32×48 전환 절차는
`docs/art/sprite-layouts-m1.md` 5.2 참고.

## 2. 외곽선 · 명암 규칙

- **외곽선**: 1px 다크 외곽선을 유지하되 순검정(#000000)은 쓰지 않는다 — 해당 오브젝트의 최암부
  색상을 더 어둡게 낮춘 색(예: 하틀랜드 잉크 컬러 `#141b1b`)을 외곽선으로 쓴다. 캐릭터·몬스터·주요
  소품에 적용, 배경 타일은 외곽선 없이 면 대비로만 구분(타일 이음새가 티 나지 않게).
- **명암 단계**: 오브젝트당 **3단계**(베이스 / 그림자 1단 / 하이라이트 1단)를 기본으로 하고, 캐릭터
  얼굴·무기 등 시선이 모이는 부위만 4단계까지 허용한다. 그러데이션(안티에일리어싱) 금지 — 도트 경계는
  항상 계단식으로 딱 떨어지게.
- **그림자**: 캐릭터·몬스터 발밑에 반투명 타원 그림자(고정 크기, 오브젝트 이동에만 따라감 — 점프 등
  높이 변화가 없으므로 그림자 크기 변화 애니메이션은 불필요).
- **라이팅**: 2D 다이나믹 라이트(횃불·마법 발광)는 CanvasModulate + Light2D 조합, 시간대별 컬러
  그레이딩은 월드 전역 셰이더/CanvasModulate로 처리(개별 스프라이트에 베이크하지 않음 — 밤/낮 전환이
  실시간이어야 하므로).

## 4. 애니메이션 프레임 규격

| 동작 | 프레임 수 | 루프 | 비고 |
|---|---|---|---|
| 이동(Walk) | 6f | 반복 | 4방향 각각 6f = 총 24f. M1 플레이스홀더는 소스 제약으로 4f 사용 중(교체 시 6f로 보강) |
| 공격(Attack) | 4~6f | 1회 | 콤보 단계별로 별도 클립. 4방향 필요 — 원작 팩엔 1방향뿐이므로 신규 제작 필수 |
| 유휴(Idle) | 4f | 반복 | **개성 동작 필수**(눈 깜빡임·하품·두리번거림 등 최소 1종). 4방향 각 4f |
| 피격(Hurt) | 2~3f | 1회 | 짧게 — 경직 시간과 동기화 |
| 사망(Dead) | 3~4f | 1회 정지 | 마지막 프레임에서 정지 후 상위 시스템이 페이드 처리 |
| 예고(Telegraph, 몬스터) | 고정 프레임 불필요 | — | 색 점멸/장판 표시 등 이펙트로 대체 가능(현재 M1 슬라임 방식) |

- 프레임레이트 기준: 이동 8fps 안팎(현재 M1 SpriteFrames `speed=8.0`), 유휴 4fps 안팎(`speed=4.0`).
  최종 수치는 game-designer/godot-engineer와 체감 조정.
- 몬스터 골격 재사용 시에도 이 표의 프레임 수를 그대로 따른다 — 골격만 같고 프레임 수가 다르면
  팔레트 스왑 변종끼리 타이밍이 어긋난다.

## 5. 네이밍 규칙

```
chr_<이름>_<동작>_<프레임수>f.png       예) chr_fin_walk_6f.png, chr_fin_idle_4f.png
chr_<이름>_<동작>_<방향>_<프레임수>f.png  예) chr_fin_attack_down_4f.png  (방향 구분 필요한 경우만)
mon_<몬스터id>_<동작>_<프레임수>f.png    예) mon_horn_rabbit_walk_6f.png
mon_<몬스터id>_<변종>_<동작>_<프레임수>f.png  예) mon_slime_frost_idle_4f.png (팔레트 스왑 변종)
tile_<지역id>_<세트명>.png              예) tile_hartland_field.png
ui_<화면/요소>_<상태>.png               예) ui_button_confirm_normal.png
fx_<이름>_<프레임수>f.png               예) fx_hit_spark_4f.png
```

- `<이름>`/`<몬스터id>`는 `game/data/*.json`의 id와 반드시 일치시킨다(코드에서 문자열로 텍스처 경로를
  조립할 수 있게).
- 방향 표기는 `down/up/left/right` 4종 고정(한글·약어 혼용 금지).
- 프레임수 접미사(`_6f`)는 파일 자체가 스프라이트시트(가로 나열)일 때만 붙인다. `SeparateAnim` 방식
  (동작별 파일 분리)을 채택하는 경우 프레임 수는 파일명이 아니라 SpriteFrames 리소스에서 관리한다 —
  단, 이번 조사에서 확인했듯(§ `sprite-layouts-m1.md` 1장) **동작별 분리 파일(가로 스트립) +
  합본 시트를 함께 만들어 두면 이후 그리드 해석 오류를 원천 차단**할 수 있으므로 원작 제작 시 이
  방식을 권장한다.

## 6. 등급 색상 · 색약 아이콘 (GDD 6.1)

| 등급 | 색상 | hex(제안) | 색약 대체 아이콘 |
|---|---|---|---|
| 일반 | 흰색 | `#ffffff` | ● |
| 고급 | 초록 | `#4a7f4b` (팔레트 §3 재사용) | ▲ |
| 희귀 | 파랑 | `#3b7fd8` | ◆ |
| 영웅 | 보라 | `#8b5fbf` | ★ |
| 전설 | 주황 | `#e66a3a` (팔레트 §3 재사용) | ✦ |
| 유물 | 붉은 금색 | `#c9932f` / 테두리 `#7a2e2e` | ❖ |

- 색약 모드에서는 등급 색 + 아이콘을 **항상 병기**한다(색만으로 구분하지 않음, GDD 11장 접근성 원칙).
- 아이콘은 16×16 단색 실루엣으로 제작해 인벤토리 슬롯 우상단 8×8 배지로 축소 표시해도 뭉개지지
  않게 한다.
- 희귀·영웅 hex는 GDD에 정확한 색 지정이 없어 이번에 제안한 값이다 — game-designer/UI 합의 후 확정.

## 7. UI 아트 방향 (ui-ux-designer 합의 전 메모)

- GDD 9·11장 기준 모티프: **양피지 패널 + 나무 프레임**, 픽셀 폰트(Galmuri, `asset-sources.md` 확보
  완료).
- 팔레트는 §3 지역 팔레트와 별도로 UI 전용 중립 팔레트(양피지 베이지·나무 갈색·잉크 톤 중심)를 쓰되,
  등급 색(§6)만은 전 지역 공통으로 고정한다(등급 색이 지역마다 달라 보이면 파밍 가독성이 깨짐).
- **이 절의 정식 규격(9-slice 크기, 버튼 상태별 색, 슬롯 그리드 치수)은 ui-ux-designer와 합의 후
  별도 절/문서로 확정한다** — 이 초안 단계에서는 방향성만 기록.

## 8. 레퍼런스 링크 규칙

- 무드보드 키워드(GDD 9장): 스타듀밸리의 따뜻함 × 젤다 신들의 트라이포스급 가독성 × Eastward의
  조명 연출. 레퍼런스 이미지는 이 세 가지 축을 벗어나지 않는 선에서만 참고한다.
- **The Spriters Resource 등 립(rip) 사이트는 "참고 링크"로만 아트 바이블에 기재한다.** 파일 다운로드,
  트레이싱, 팔레트 그대로 추출 금지 — `asset-sources.md` §1 정책과 동일 기준. 이 문서에 립 사이트
  링크를 추가할 때는 반드시 다음 형식을 지킨다:

  ```
  - [참고 전용] <시리즈/캐릭터명> 프레임 수·비율 연구 — <URL> (다운로드/트레이싱 금지, 눈으로 비율만 참고)
  ```

- 현재 등록된 레퍼런스 링크: 없음(필요 시 이 절에 추가).
