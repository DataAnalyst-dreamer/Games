## 2. 방향별 실루엣 차별화 (핵심 요구사항)

기존 임시 에셋의 문제(`docs/qa/walk-animation-diagnosis.md`: 상/하 픽셀 유사도 0.935)를
해소하기 위해 **4방향이 서로 다른 조형 요소로 구분되도록 설계**했다. 검증 이미지:
`docs/art/preview/fin-directions-preview.png`.

| 방향 | 얼굴 | 방패 실루엣 | 망토 | 깃털 |
|---|---|---|---|---|
| **하(down)** | 눈·볼터치·입이 보이는 정면 얼굴 | 몸 앞에 든 **둥근 목재 방패**(왼팔) | 몸통에 가려 안 보임 | 위로 솟은 V자 이중 깃털(전방 강조) |
| **상(up)** | 얼굴 요소 전혀 없음, 투구 뒤통수 + 중앙 솔기선만 | 등에 멘 방패가 **망토 위에 겹쳐 보임** | **등 전체를 덮는 견습 망토**(핵심 차별 요소) | 투구에 가려 끝만 살짝 보임(정면 대비 훨씬 작음) |
| **좌(left)** | 옆모습 코 돌출 + 눈 1개, 진행 방향(왼쪽)을 향함 | **얇은 날 방향 세로 판**(방패 옆면, 몸 뒤쪽) | 등 쪽에 작은 삼각 자락만 | 진행 반대 방향(오른쪽)으로 수평 휘날림 |
| **우(right)** | 좌 방향을 좌우 반전 — 코·눈이 오른쪽 | 좌 방향 반전(방패 왼쪽 뒤로) | 좌 방향 반전 | 왼쪽으로 수평 휘날림 |

- **좌/우는 좌(left) 드로잉 함수를 그대로 좌우 반전해 우(right)를 만든다** — GDD가 허용한
  절약 전략(`docs/art/motion-design-reference.md` 1장 "8방향 대신 4방향 + 반전"). 별도로
  손으로 그리지 않았음을 여기 명시한다.
- 정면/후면은 "얼굴 유무 + 방패 위치(앞 vs 등) + 망토 유무"라는 3중 신호로 구분되어, 과거
  0.935 유사도 문제가 재발하지 않는다(육안 대조 결과 `fin-directions-preview.png` 참고).

## 3. 프레임 타이밍 표 (SpriteFrames 반영용)

프레임 수는 `docs/brd/04-decisions.md` D-133 확정치. 타이밍 배분은
`docs/art/motion-design-reference.md`의 "선딜-타격-후딜 3단, 불균등 홀드" 원칙을 그대로 적용했다.

### 3.1 대기 (Idle, 4프레임 반복, 총 주기 1400ms)

| 프레임 | 내용 | 홀드(ms) |
|---|---|---|
| 0 | 중립 자세 | 400 |
| 1 | 숨 들이쉬며 몸 1px 상승 | 350 |
| 2 | 숨 정점 + **검자루 고쳐 잡기**(개성 동작, 하/좌/우 공통) | 350 |
| 3 | 숨 내쉬며 복귀 + **눈 깜빡임**(down 방향만 육안 확인 가능) | 300 |

- SpriteFrames는 프레임별 `duration`(초 단위 배수)으로 지정: 0.4 / 0.35 / 0.35 / 0.3 (기준
  1.0 = 1000ms일 때 배수). 등속 재생만 지원한다면 `speed=4.0`(250ms/프레임 평균) 근사치로 대체.

### 3.2 걷기 (Walk, 8프레임 반복, 10fps 기준 총 주기 800ms)

| 프레임 | 내용 | 홀드(ms) |
|---|---|---|
| 0 | 좌다리 최대 전진(접지) | 110 |
| 1 | 패싱(다리 교차, 몸 바운스 정점) | 90 |
| 2 | 우다리 최대 전진 방향 전환 시작 | 100 |
| 3 | 패싱 | 100 |
| 4 | 우다리 최대 전진(접지) | 110 |
| 5 | 패싱(바운스 정점) | 90 |
| 6 | 좌다리 전환 시작 | 100 |
| 7 | 패싱 | 100 |

- 균등 재생 시 **10fps**(100ms/프레임)를 기본값으로 제안(미리보기 GIF 기준). 발 접지 프레임
  (0·4)을 살짝 더 길게(110ms) 홀드하면 "불균등 홀드" 원칙에 더 가까워진다 — 엔진에서 프레임별
  duration 배열 지원 시 위 표 값을 그대로 쓴다.

### 3.3 공격 (Attack, 6프레임 1회, 총 소요 약 480ms) — 선딜/타격/후딜 3단

| 구간 | 프레임 | 내용 | 홀드(ms) |
|---|---|---|---|
| 선딜 | 0 | 검을 들어올리기 시작 + 방패 몸에 당김 | 120 |
| 선딜 | 1 | **가장 크게 과장된 준비 자세**(검 최고 높이, 방패 최대로 당김) | 130 |
| **타격** | **2** | **가장 짧은 프레임** — 방패를 앞으로 내지르며 검을 내려침(핀의 "저스트 가드" 반사 성격 반영: 방패가 먼저 나간다) | **30** |
| 후딜 | 3 | 방패·검 회수 시작 | 90 |
| 후딜 | 4 | 중립에 가까워짐 | 80 |
| 후딜 | 5 | 중립 복귀 | 80 |

- 총합 530ms 근사. 타격 프레임(2)이 표에서 가장 짧다 — 요구 조건 충족.
- 뒤(up) 방향은 등에 멘 장비가 고정 소품이라 실루엣 변화가 작다(양어깨가 들렸다 떨어지는
  정도) — 의도된 절충이며, 전투 중 플레이어가 후면 공격 프레이밍을 볼 일이 드물다는 점을 근거로
  우선순위를 낮췄다. 체감상 부족하면 2차 패스에서 보강 후보.

### 3.4 피격 (Hurt, 2프레임 1회, 총 소요 약 220ms)

| 프레임 | 내용 | 홀드(ms) |
|---|---|---|
| 0 | 크게 젖혀짐 + 눈 질끈 감음(윈스) | 120 |
| 1 | 절반 정도 복귀 | 100 |

- 프레임 자체는 최소화하고 `hit_flash.gd`(흰 플래시)·넉백 Tween에 정보 전달을 맡긴다
  (`motion-design-reference.md` 6장 권고와 일치).

## 4. 원점(피벗) · 히트박스 권장값

- **원점(피벗)**: 셀 내부 좌표 **(16, 43)** — 셀 하단(y=48)에서 위로 5px 지점, 발밑 그림자
  중심과 일치(art-bible.md §1 "발밑 4~6px" 규칙 충족).
- `Sprite2D`/`AnimatedSprite2D`를 `centered=true`(기본값, 텍스처 중심 = (16,24))로 쓸 경우:
  `offset = Vector2(0, -19)` 로 설정하면 발밑(16,43)이 노드 원점과 일치한다.
- **이동 충돌(캡슐/원형)**: 반경 6px, 중심 (16, 40) — 발 주변만 감싸 벽·몬스터 충돌이 상반신
  실루엣과 어긋나지 않게 한다.
- **피격 판정(히트박스, 몸통 기준)**: 20×26px, 중심 (16, 26) — 튜닉 몸통 전체를 덮는 크기.
- **공격 판정(무기 히트박스)**: 방향별로 무기 끝 좌표가 다르므로 코드에서 방향 벡터 기반
  오프셋 판정을 유지 권장(스프라이트에 고정 좌표를 박지 않음) — 참고로 정면(down) 기준 검 끝은
  타격 프레임(2)에서 대략 (26, 20) 부근.
- 위 수치는 제안값이며, 실제 충돌 튜닝은 godot-engineer가 `game/scripts/tuning.gd`에서 조정한다.

## 7. 남은 이슈 / 후속 제안

- 뒤(up) 방향 공격 모션은 등짐 장비가 고정이라 다른 방향보다 변화가 작다 — 사용자 검토 후
  부족하다는 피드백이 오면 어깨 흔들림 폭을 키우거나 검을 뽑아 드는 프레임을 추가하는 2차
  패스를 제안한다.
- 이번 시안은 **핀 1종만** 대상이며(D-135), 승인 전까지 리라·모리·브람 및 몬스터 32×48
  전환에는 착수하지 않는다.
- 엔진 통합(`Player.tscn`/`SpriteFrames` 교체, `set_facing()` 로직과의 연동)은 시안 승인 후
  별도 단계로 진행 — 이번 작업 범위에서 `.gd`/`.tscn`은 건드리지 않았다.

## 부록 Z. 디렉터 검토 결과 (2026-09-10) — **이 시안은 프로덕션 채택 보류**

이 문서의 규격·타이밍·피벗·히트박스 수치는 유효하며, 앞으로 어떤 경로로 아트를 확보하든
그대로 쓴다. 다만 **동봉된 스프라이트 자체는 프로덕션에 쓰지 않는다.**

- **달성된 것**: D-130~D-135 규격 준수(32×48, 4/8/6/2프레임, 하틀랜드 팔레트 13색, 새 색 0종).
  네 방향 실루엣 구분이라는 최우선 요구사항은 실제로 해결됐다(얼굴 / 투구 뒤통수+솔기 /
  옆모습 코+방패 각도). `docs/qa/walk-animation-diagnosis.md`가 지적한 상·하 유사도 0.935
  문제는 이 방식으로 해소된다 — **이 구분 방법 자체는 이후 어떤 아트를 쓰든 계승한다.**
- **미달인 것**: 그림의 완성도. 몸통에 명암·형태감이 없고(단색 사각형), 머리가 덩어리로
  뭉치며, 얼굴 인상이 설정("씩씩한 견습 기사")과 어긋난다. 깃털·검이 몸에 붙어 보이지 않는다.
  픽셀 수는 기존 임시 애셋의 6배지만 **체감 완성도는 오히려 낮다** — 기존 Ninja Adventure
  애셋은 전문 도터의 수작업이고 이쪽은 좌표 기반 프로그램 생성이라, 이 방식의 한계다.
- **결론**: 프로그램 생성으로는 이 이상 올리기 어렵다고 판단해 추가 다듬기를 중단했다.
  이 문서와 스프라이트는 **규격 검증용 레퍼런스 / 외주 발주서**로 보존한다.
