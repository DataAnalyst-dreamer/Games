## 0. 캐릭터 설정 요약 (변경 없음)

- **정체성**: 대륙 변방 국경 마을 수비대 견습 기사. 명령대로 정면만 지키다 다른 곳의 위험을
  놓쳤던 경험 때문에 먼저 방패를 들고 동료를 지키려 한다(`docs/story/characters.md` 2.1).
- **비주얼**: 은색 열린 투구 + 코럴레드 깃털, 갈색 앞머리, 황토색 튜닉, 세이지그린 짧은 망토,
  갈색 부츠. 검은 캐릭터 본인 오른손, 방패는 왼손. 2.5등신 SD, 톤은 "귀엽지만 씩씩함"
  (art-bible 톤 한 줄 요약 "아기자기하고 따뜻하다"를 벗어나지 않음).
- **저작권 주의**: 프롬프트에 특정 상용 게임·캐릭터 이름을 넣지 않는다 —
  `ai-sprite-pipeline.md` §2.3 참고.

## 1. 규격 요약 (D-140)

- 몸체 작업 영역 **64×96px**. 검·방패·깃털·공격 궤적은 이 영역에 억지로 욱여넣지 않는다.
- 모션 캔버스는 **96×128px**(패딩 포함), 발 기준점 **(48,112)**. 몸체는 캔버스 안에서 수평 중앙.
- 게임 기준 **FHD 1920×1080**.
- **PixelLab 사용 시 주의**: PixelLab의 캐릭터 생성 API는 `size`를 몸체가 아니라 **캔버스
  전체**로 받고, 문서상 본체가 캔버스 높이의 약 60%라는 안내가 있다(`ai-sprite-pipeline-options.md`
  "PixelLab 확인 범위"). 64×96을 그대로 `size`로 넣으면 몸체 64×96이 나온다고 가정하지 않는다 —
  실제 반환 크기·알파를 프레임마다 측정해서 확인한다(측정은 `normalize_ai_sheet.py`의 지터
  리포트가 자동으로 해 준다).

## 2. 사용 순서 — 정면 확정 → 접지·형태 고정 → 걷기 (독립 프레임 이어붙이기 금지)

1. **정면 1프레임만 먼저 생성·확정**한다(`fin-front-64-prompt.txt`, 필요시 소형 비교판
   `fin-front-48-prompt.txt`). 외곽선·눈·투구 홈·장비 경계가 정리된 이 한 장을 이후 모든 방향·
   모션의 **공통 기준(참조 이미지)**으로 쓴다.
2. 사용자 승인 전에는 다음 단계로 넘어가지 않는다(D-135 원칙 계승) — `fin-resolution-review.md`가
   이미 정면 B를 승인 기준으로 확정했으므로, 그 결과물의 픽셀 정리가 끝난 뒤 진행한다.
3. **걷기는 승인된 정면 1장을 참조/시작 이미지로 넣어 한 번에 생성**한다(`fin-cq-walk-prompt.txt`).
   **금지**: 각 프레임을 따로따로 생성한 뒤 붙여서 걷기 시트를 만드는 방식 — 프레임마다 별도로
   생성하면 형태·비율·장비 위치가 프레임마다 달라져 §3의 반려 사유가 그대로 재발한다.
4. 산출물은 `docs/art/ai-sprite-pipeline.md` §4 워크플로대로 `normalize_ai_sheet.py`에 넣어
   지터 리포트로 접지·실루엣 안정성을 **수치로** 재확인한다 — 육안 검수만으로 통과시키지 않는다.
5. 4방향이 필요한 모션(걷기·공격·피격)에서 좌/우는 좌(left) 결과를 좌우 반전해 만든다
   (`character-fin-spec.md` §2가 이미 정리한 절약 전략, 규격 변경과 무관하게 유효) — 단, 이번
   64×96 정면 승인 과정에서 반전 시 검/방패 좌우가 바뀌지 않는지 반드시 확인한다
   (`fin-artist-pilot-brief.md` §5 "단순 전체 미러로 완성 처리하지 않는다" 참고).

### 이번엔 무엇을 다르게 하는가 — 지난 반려 사유 (`docs/qa/checkpoint-20260919.md`)

PixelLab 걷기 v1~v3는 **전부 정면 승인 이미지를 참조로 넣은 상태에서도** 반려됐다 — 원인은
"재생이 안 됨"이 아니라 **동작 품질**이었다:

- **v1**(자유 문장 프롬프트 + `animate_image`): 검이 크게 휘둘리고, 몸이 옆으로 돌며, 실루엣이
  좁아짐 — 정면과 다른 캐릭터처럼 보임.
- **v2**(어깨 교차 시험, 역시 자유 문장): 웅크림/옆으로 피하는 듯한 자세가 섞여 나옴.
- **v3**(캐릭터 레퍼런스 + 표준 걷기 템플릿): v1·v2보다는 안정적이었으나 **8프레임을 요청해도
  6프레임만 반환**했고, 몸체 크기가 입력(66×96)과 출력(68×96) 사이에서 흔들림 — §3 체크리스트
  항목 1·3·6에서 반려.

즉 "정면 참조를 넣었는가"만으로는 통과되지 않는다. 이번 재시도에서 추가로 지킬 것:

- 정면 참조 이미지 자체의 **픽셀 정리(외곽선·눈·투구 홈)가 끝난 뒤**에만 걷기 생성을 시도한다
  (`fin-64-production-spec.md` "다음 제작 단위" 참고) — 아직 거친 AI 시안을 그대로 참조로 쓰지
  않는다.
- 생성 결과의 프레임 수·크기가 요청과 정확히 같은지 **다운로드 즉시 확인**하고, 다르면 그 자리에서
  반려 처리한다(6프레임만 나온 v3처럼 "일단 받아서 부족분을 복제"하지 않는다).
- `normalize_ai_sheet.py`의 `max_silhouette_size_jitter_px`(2px 초과 시 경고)로 v1급 실루엣
  붕괴를 객관적으로 걸러낸다 — 육안 인상("괜찮아 보인다")만으로 통과시키지 않는다.
- 이 경로가 다시 반려되면 `docs/art/fin-artist-pilot-brief.md`(외주 픽셀 아티스트 견적 브리프)
  경로를 사용자와 검토한다 — AI 생성 재시도를 무한정 반복하지 않는다.

## 3. 폐기된 32×48 프롬프트 변형 (참고용, 재사용 금지)

이전 버전(D-130~D-133 기준)의 PixelLab 변형 A/B/C 프롬프트(32×48 셀, 4방향 대기/걷기 8프레임/
공격 6프레임/피격 2프레임)는 D-140으로 규격이 바뀌며 폐기됐다. 프레임 수 자체(걷기 8·공격 6·
대기 4·피격 2)는 D-133 그대로 유효하니 재사용하되, 셀 크기·피벗 수치는 반드시
`fin-64-production-spec.md`를 따른다. 옛 프롬프트 전문이 필요하면 git 이력(커밋 `8b50166`)에서
확인할 수 있다 — 이 문서에는 다시 옮기지 않는다.

## 4. 생성 후 처리 (필수)

1. 생성 결과 PNG를 `assets-inbox` 브랜치에 업로드.
2. `tools/art/normalize_ai_sheet.py`로 정규화(기본값이 96×128 셀·발 기준점 (48,112) —
   `docs/art/ai-sprite-pipeline.md` §4 예시 명령 참고).
3. `docs/art/ai-sprite-pipeline.md` §3 체크리스트 7항목 통과 확인.
4. `docs/art/LICENSES.md`에 툴·플랜·생성일·프롬프트·상업적 이용 조건 기입(§2.2 형식) — **이 기입이
   없으면 반입 불가**.
5. 승인 후 `game/assets/sprites/characters/fin/`에 배치, godot-engineer에게 SpriteFrames 통합 요청.
