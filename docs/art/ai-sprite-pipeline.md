## 1. 툴 역할 분담 — 요약만, 상세는 `ai-sprite-pipeline-options.md`

| 툴 | 이 프로젝트에서의 용도 | 상태 |
|---|---|---|
| **PixelLab.ai**(`animate_image`/`create_character` v3, MCP·REST) | 승인된 정면 1프레임을 참조로 방향별 걷기·공격 등 모션 생성 | 조사 완료, 걷기 시험 v1~v3 진행 — 전부 반려(`checkpoint-20260919.md`) |
| 내장 이미지 생성 도구 | 정면 시안·개념 비교(A/B), 초기 컨셉 시트 | 정면 B 채택(D-140), 걷기는 별도 시험 필요 |
| Higgsfield(또는 동급 고해상도 생성기) | 타이틀 화면 일러스트, 포트레이트, 홍보 키비주얼만 — 인게임 스프라이트 절대 아님 | 조사만 완료, 미연결 |
| 완성도 있는 외부 애셋 팩 / 외주 픽셀 아티스트 | AI 생성이 계속 반려될 경우의 대체 경로 | `docs/art/fin-artist-pilot-brief.md`(미발송 견적 브리프) |

- 순서 원칙(D-135 계승): **정면 1프레임 확정 → 승인 → 접지·형태 고정 → 걷기 → 나머지 모션**.
  구체적 실행 순서·이번에 무엇을 다르게 하는지는 `brief-fin-pixellab.md` §사용 순서 참고.
- 세 경로 모두 계정 기반 웹 서비스이거나 사람 개입이 필요해 아트 디렉터(이 세션)가 직접 실행할 수
  없다 — 브리프를 작성해 사용자에게 전달하고, 생성된 결과물을 받아 정규화·검수한다.

## 2. 라이선스·기록 규칙 (D-137·D-138, 유효)

### 2.1 등급 "AI-생성"

`docs/art/asset-sources.md` §1의 등급표(A/B/C/✕)에 추가된 다섯 번째 등급:

| 등급 | 조건 | 저장소 커밋 | 용도 |
|---|---|---|---|
| **AI-생성** | 사용자가 PixelLab.ai/내장 이미지 생성 도구/Higgsfield 등에서 직접 생성. 해당 서비스 약관의 상업적 이용 조건을 사용자가 확인·기입해야 반입 가능 | 조건부(아래 2.2) | 프로토타입 + (약관이 상업 이용·재배포를 허용하는 한) 출시 버전 |

### 2.2 `LICENSES.md` 기입 없이는 `game/assets/`에 넣지 않는다

AI 생성물은 다음 정보가 **모두** `docs/art/LICENSES.md`에 한 행으로 기록되어야 반입 가능하다:

| 필수 기입 항목 | 설명 |
|---|---|
| 반입일 | 정규화 스크립트를 돌려 `game/assets/`에 넣은 날짜 |
| 툴 · 플랜 | 예: "PixelLab.ai (Trial)", "내장 이미지 생성 도구" — 플랜별로 상업 이용 조건이 다르므로 반드시 플랜명까지 기입 |
| 생성일 | 실제 생성 실행 날짜(플랜 만료·약관 개정 시점 추적용) |
| 프롬프트/작업 전문 | 실제로 사용한 프롬프트 또는 API 파라미터 원문(재현·감사 가능하도록) |
| 상업적 이용 조건 | **사용자가 해당 서비스의 이용약관/요금제 페이지를 직접 확인한 뒤** 요지를 요약해 기입. **AI 디렉터가 약관을 대신 추정해서 기입하지 않는다** — 확인 안 된 경우 "확인 필요"로 비워 두고 반입을 보류한다 |
| 위치 | 반입 등급에 따라 `game/assets/` 또는 `game/assets_local/` 경로 |

- 위 표가 비어 있는 열이 하나라도 있으면 **그 애셋은 `game/assets/`에 넣지 않는다.** `assets-inbox`
  브랜치에 올린 원본 PNG는 승인 전까지 그 브랜치에만 존재한다(§4 워크플로 참고).
- 상업적 이용 조건이 "재배포 금지"인 플랜이면 asset-sources.md의 B등급과 동일하게
  `game/assets_local/`(git 제외)에만 둔다.

### 2.3 저작권 주의 — 프롬프트에 실명 금지

PixelLab/내장 도구/Higgsfield 프롬프트에 **특정 상용 게임·시리즈·캐릭터 이름을 넣어 "그 스타일로"
생성 요청하지 않는다**. 일반 스타일 기술어만 사용한다 — 구체 예시는 `docs/art/brief-fin-pixellab.md`
및 `docs/art/fin-front-64-prompt.txt`/`fin-cq-walk-prompt.txt` 참고.

## 3. 수용 체크리스트 (품질 게이트)

생성물이 `game/assets/`에 들어가기 전에 아래 항목을 **전부** 통과해야 한다. 셀·프레임 수치는
`fin-64-production-spec.md`(D-140 몸체 64×96 / 캔버스 96×128 / 발 기준점 (48,112) /
걷기 8프레임 설계표)를 그대로 인용한다.

| # | 항목 | 기준 | 검사 방법 |
|---|---|---|---|
| 1 | 셀 크기 | 캔버스 96×128px(몸체 64×96px가 그 안에 패딩 포함으로 배치) | **스크립트**: `normalize_ai_sheet.py`(기본값 `--cell 96x128`)가 소스 셀 크기를 받아 정확히 잘라내고 출력 셀을 강제 리사이즈한다. 소스 그리드 해석(열/행 개수)이 잘못되면 캐릭터가 잘려 보이므로 **정규화 후 미리보기 PNG를 육안으로도 반드시 확인**한다 |
| 2 | 네 방향 실루엣 즉시 구분 | down(정면)/up(뒤통수)/left/right가 실루엣만으로 구분됨 | **육안**: `<name>_preview.png`(4배 확대, 그리드선 포함)를 네 방향 나란히 놓고 비교. 얼굴 유무·투구 깃털 방향·망토 유무 등 방향 구분 장치가 실제로 반영됐는지 확인(이 원칙은 D-130 규격 폐기와 무관하게 계승) |
| 3 | 프레임 간 지터 없음(옷·무기 형태 유지) | 프레임마다 실루엣 위치·크기가 흔들리지 않음 | **스크립트 + 육안**: `<name>_report.json`의 `max_position_jitter_px`(발밑 정렬 후 위치 오차)와 `max_silhouette_size_jitter_px`(실루엣 bbox 크기 편차 — **핵심 지표**, 2px 초과 시 스크립트가 경고 출력)를 확인. PixelLab 걷기 v1은 이 항목에서 실패했다(검이 크게 휘둘리고 실루엣이 좁아짐 — `checkpoint-20260919.md`) |
| 4 | 1px 외곽선 | 순검정(#000000) 아님, art-bible §2 기준 잉크색 사용 | **육안**: 확대 미리보기에서 외곽선 색 스포이드 확인 |
| 5 | 팔레트 32색 이내 | 지역별 32색 팔레트(art-bible §3) 안에서만 색 사용 | **스크립트**: `--quantize` 옵션이 art-bible.md §3 표에서 hex를 자동 추출해 최근접 색으로 강제 스냅한다. 검사는 "양자화 전/후 이미지를 나란히 비교해 캐릭터가 지나치게 다르게 보이지 않는지" 육안 확인으로 전환 |
| 6 | 걷기 8 · 공격 6 · 대기 4 · 피격 2프레임 | D-133 기준 프레임 수 정확히 일치(걷기 8프레임 설계는 `fin-64-production-spec.md` 표를 그대로 따른다 — 왼발 접지/지지/오른발 통과.../좌우 대칭 반주기 8단) | **스크립트**: 출력 파일명에 자동으로 `_<프레임수>f` 접미사가 붙으므로(`chr_fin_walk_8f.png`) 파일명만 봐도 즉시 확인 가능. 프레임 수가 기준과 다르면 반입 전 반려(예: 걷기 v3는 6프레임만 반환해 이 항목에서 반려) |
| 7 | 발 기준점 정렬 | 96×128 캔버스 안에서 발밑이 고정 좌표 **(48,112)**에 정렬. 단 이는 패딩 규칙이지 모든 프레임의 최하단을 자동 정렬하라는 뜻이 아니다 — 접지 발은 바닥을 지키고 공중 발·몸통은 의도된 높이로 움직여야 한다(`fin-64-production-spec.md`) | **스크립트**: `normalize_frame()`이 각 프레임의 불투명 픽셀 바운딩박스 하단-중앙을 목표 피벗 좌표로 강제 이동시킨다(정렬 실패 시 자체 테스트가 실패하도록 검증됨). 육안 확인은 미리보기 그리드선 대비 발 위치로 교차검증 |

- 7개 항목 중 하나라도 반려되면 **프롬프트를 조정해 재생성**하거나(`brief-fin-pixellab.md` 참고),
  정규화 스크립트 인자(소스 셀 크기·팔레트 등)를 다시 맞춰 재실행한다.
- 최종 승인은 아트 디렉터(이 역할) + game-designer(히트박스·타이밍 정합성) 확인을 함께 받는다.

## 4. 워크플로

```
1. 브리프 확인(아트 디렉터, 이 저장소)
   └─ docs/art/brief-fin-pixellab.md의 사용 순서·주의사항 + fin-front-64-prompt.txt /
      fin-cq-walk-prompt.txt 프롬프트 원문

2. 생성(사용자, PixelLab.ai 또는 내장 이미지 생성 도구에서 직접 실행)
   └─ 정면 1프레임 → 승인 → 그 프레임을 참조로 걷기 생성(독립 생성 프레임을 이어붙이지 않는다)

3. assets-inbox 브랜치에 PNG 업로드(원본 그대로, 가공 전 상태 — 추적성 확보)

4. tools/art/normalize_ai_sheet.py로 정규화
   └─ 배경 투명화 → 팔레트 양자화 → 발 기준점(48,112) 정렬 → 96×128 셀 시트 생성
   └─ 동시에 미리보기 PNG(4배, 그리드선) + 방향별 GIF + 지터 리포트 JSON 생성
   예: python3 tools/art/normalize_ai_sheet.py --mode sheet --input inbox/fin_walk_raw.png \
       --src-cell-w 96 --src-cell-h 128 --cols 8 --rows 4 --name chr_fin_walk \
       --transparent-bg --bg-color 255,0,255 --quantize \
       --out game/assets/sprites/characters/fin/_normalized
   (32×48 레거시 산출물을 다룰 때만 `--cell 32x48 --pivot 16,43`을 덧붙인다)

5. 미리보기로 검수(§3 체크리스트 7항목)
   └─ 반려 시 2번 또는 4번으로 되돌아감

6. 승인
   └─ LICENSES.md에 §2.2 표 형식으로 행 추가(이게 없으면 다음 단계 진행 불가)

7. game/assets/sprites/characters/<slug>/ 배치
   └─ 네이밍 규칙(art-bible §5)을 따름: chr_<이름>_<동작>_<프레임수>f.png

8. SpriteFrames 통합(godot-engineer)
   └─ 이 단계는 이 세션 범위 밖 — 코드(.tscn/.gd) 수정 없음
```

- 3~4번은 여러 번 반복될 수 있다(생성물이 한 번에 체크리스트를 통과하는 경우는 드물다 —
  PixelLab 걷기 v1~v3가 그 예). 매 반복마다 `assets-inbox`에는 새 파일명(버전 접미사)으로 올려
  이전 시도를 덮어쓰지 않는다.
- 모든 시도가 반려되면 `docs/art/fin-artist-pilot-brief.md`(외주 픽셀 아티스트 경로)를 다음
  단계로 검토한다 — 이 문서 자체가 그 결정을 내리지는 않는다.
- 몬스터 팔레트 스왑 변종(art-bible §9 매트릭스)도 동일 파이프라인을 쓴다 — 단, 이 스크립트는
  "이미 있는 색을 팔레트에 맞춰 스냅"하는 용도이지 "색 자체를 창의적으로 재배색"하지는 않으므로,
  완전히 다른 색상 콘셉트가 필요하면 생성 단계에서 프롬프트로 다시 요청한다.
