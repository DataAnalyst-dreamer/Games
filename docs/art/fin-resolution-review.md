# 핀 정면 해상도 비교 / FHD 기준

2026-09-12 · D-139~140 · 사용자 64×96 규격 선택 완료. 전 동작 완성·게임 적용 승인을 의미하지 않음.

사용자 답변 “64 x 96 으로 진행해줘”에 따라 B를 제작 기준으로 선택했다. 48×72 추가 비교는 종료한다. 정면 기준 프레임 정리와 걷기 제작 규칙은 `fin-64-production-spec.md`를 따른다.

## 결과

FHD 1920×1080 기준으로 64×96 몸체 목표를 우선 후보로 추천한다. 새 정면 B는 눈·앞머리·투구의 구분과 방패 테두리를 A보다 잘 보존한다. 2배 표시 시 캐릭터 높이 192px, FHD 높이의 17.8%이다. A는 144px/13.3%로 탐험 공간을 덜 가리지만 얼굴에 쓸 픽셀이 적다. 이 비율은 카메라 줌과 렌더 스케일을 합친 표시 배율 2를 가정하며, 줌 2에 별도 창 확대 2를 다시 곱하지 않는다.

## 파일

- `preview/fin-resolution/index.html`: 원본/2배/같은 높이 선택 비교판. FHD 원본 크기라 좁은 창에서는 가로 스크롤. 브라우저 배율과 OS 배율에 따라 실제 물리 픽셀은 달라진다.
- `preview/fin-resolution/comparison.png`: 원본 크기와 정수 확대 디테일 비교. 960×540 편집판이며 게임 해상도가 아니다.
- `preview/fin-resolution/fhd-scale.png`: 1920×1080 정지 크기 검토판. 실제 게임 배경/플레이 캡처가 아니다.
- `preview/fin-resolution/front-48.png`, `front-64.png`: 장비 포함 실제 PNG 크기 51×72, 66×96. 몸체 목표 규격과 전체 패딩 셀 규격을 혼동하지 않는다.
- `fin-front-48-prompt.txt`, `fin-front-64-prompt.txt`: 내장 이미지 도구에 보낸 정확한 개별 프롬프트.
- `tools/compare_fin_resolution.py`: 승인된 코드 기반 추출·비교 산출 재현. 네트워크/API 호출 없음.

## 한계와 검증

승인 콘셉트를 참조해 두 정면 시안을 각각 새로 생성했다. 기존 걷기 그림을 단순 확대하지 않았다. 하지만 요청한 1024×1024 출력/8배 정렬 논리 격자와 달리 실제 결과는 모두 1254×1254였다. 따라서 이를 정밀한 픽셀 원화로 인정하지 않는다. 마젠타 배경 추출 후 BOX 축소·이진 알파 처리했고 기존의 일괄 32색 축소는 사용하지 않았다. 두 시안은 포즈와 장비 구성이 유사하지만 머리·몸 비율에도 차이가 있어 해상도만 바뀐 통제 실험은 아니다.

정적 비교판을 직접 확인했다. 실제 엔진 재생·걷기·전투·UI 회귀검증은 이번 범위에 포함하지 않는다. HTML 버튼 동작은 코드 작성 상태이며 브라우저 자동 검증 미수행. 원본 및 처리본은 보존했다. 생성물의 독점권이나 법률 검토 완료를 주장하지 않는다.

## 다음 단계

1. 64×96 후보의 외형을 기준으로 눈·투구·외곽선 픽셀을 고정한 정면 기준 프레임 완성. 정밀 픽셀 정리 없이 애니메이션 확장하지 않는다.
2. 같은 머리/몸통 형태를 공유하면서 좌우 발 접지·통과·체중 이동을 설계. 기존 독립 생성 8프레임을 재활용하지 않는다.
3. 정면 걷기를 실제 엔진에서 확인한 뒤 후면/측면 제작.
4. T05에서 FHD viewport·카메라·월드 좌표·HUD/메뉴 글자와 패널 크기를 함께 이관. 현재 실행 viewport 640×360/출력 창 1920×1080은 남아 있으며, 이미 native FHD 이관 완료했다고 보고하지 않는다.
