# 기존 기사 대역 손–무기 결합 명세 v1

## 범위

사용자가 개선된 타격감은 긍정적으로 평가했으나 무기를 손에 들고 있는 느낌이 부족하다고 했고, 같은 독립 샘플에서 손–손잡이 결합을 진행하도록 승인했다. 이 명세는 **기존 대역 원화의 실제 주먹 위치**를 연결하는 작은 구현 입력이다. 새로운 핀 원화, 팔/몸통 애니메이션 제작, 본편 이관 또는 승인된 핀의 손잡이 정체성 변경은 아니다.

소유 산출물은 [weapon_rig.json](../../../../prototypes/quarter-view-lab/weapon_rig.json) 및 이 설명이다. actor/combat 렌더링·판정은 전투 담당, 실행/캡처는 엔진 담당 소유다. 명세 작성자는 자신의 명세를 독립 DA하지 않는다.

## 원본 직접 확인

- [기존 대역 atlas](../../../../prototypes/quarter-view-lab/assets/proxy-knight.png)를 원래 크기로 직접 view했다. 전체 64×128, 셀 16×16, 네 방향 열과 기존 동작 행을 가진다.
- 원본 SHA256: `D20EACC1334ABE43BD69C9298F55E383B86A1E71C726973240EB2BB0C4F5F08C`.
- 원본 PNG를 읽기 전용으로 픽셀 조사했다. 팔 끝에서 보이는 붉은/주황 픽셀은 `#D14B34`와 `#EF914F`이며, 주변에는 원래 외곽선 `#141B1B`, 의상/팔의 `#4E484A`·`#3B3643` 등이 있다. 단순 색만으로 자동 손 검출한 것이 아니라 네 방향의 idle/뻗은 주먹 자세 문맥과 함께 선택했다.
- 새 image generation, 원본 이미지 확대/축소/절단/채색/alpha 편집, atlas 재조립을 하지 않았다. 기존 원본의 같은 region을 엔진에서 다시 그리는 것은 별도 runtime 렌더링이다.

## 좌표 계약

좌상단을 (0,0), 원본 픽셀 (x,y)의 셀 영역을 `[x,x+1]×[y,y+1]`로 본다. 손잡이 중심은 원래 유색 주먹 영역의 중심이다. **JSON 좌표에 임의로 +0.5를 다시 더하지 않는다.**

`actorLocal = (hand_socket_px - [8,8]) * 4 + [0,-24]`

| 방향 / atlas 열 | idle row0 손 중심 | attack row4 손 중심 | idle → attack actorLocal | 실제 주먹의 핵심 픽셀 |
|---|---|---|---|---|
| down / 0 | (13,14) | (14,12) | (20,0) → (24,-8) | idle x12–13,y13–14; attack x13–14,y11–12 |
| up / 1 | (3,14) | (5,1) | (-20,0) → (-12,-52) | idle x2–3,y13–14; attack x4–5,y0–1 |
| left / 2 | (8,14) | (1,12) | (0,0) → (-28,-8) | idle x7–8,y13–14; attack x0–1,y11–12 |
| right / 3 | (8,14) | (15,12) | (0,0) → (28,-8) | idle x7–8,y13–14; attack x14–15,y11–12 |

네 방향은 기존 dominant-axis 열 선택을 그대로 따른다(절댓값 동률은 가로). 이동/조준 8방향과 새 8방향 원화는 다른 개념이다. 몸체가 실제 row0/row4로 바뀌는 프레임에 socket도 함께 선택한다. 손만 별도로 보간해 몸에서 미끄러지게 하거나 PNG 전체를 흔들지 않는다.

항상 들고 있는 무기를 구현할 때 걷기 row1/2/3의 손 위치도 필요하다. 직접 조사 결과 idle과 최대 몇 원본 픽셀 다르므로 JSON의 `walk`에 별도 좌표를 기록했다. row2는 idle과 손 위치가 같다. down row3 (13.5,12), up row3 (3,10.5)의 반 픽셀 값은 1픽셀 폭/높이 손 영역의 정확한 셀 중심이며 모션 보간이 아니다. 특정 손이 원화 몸체 뒤쪽으로 들어간 프레임의 가림은 runtime에서 확인한다.

## 결합과 레이어

- 손잡이의 중심/pivot을 해당 socket에 둔다. 현재의 몸통 중심에서 회전 방향으로 일정 거리를 더한 점을 임의 손 위치로 쓰지 않는다.
- down/left/right: 원래 몸체 → 무기 → 원본 주먹 region. up: 무기 → 원래 몸체 → 원본 주먹 region. 손잡이는 손 아래에 있어야 하며 장갑을 칼 위에 그린다.
- `glove_overlay_rect_px`는 손 색 픽셀과 주변 원본 외곽선/팔 부분의 작은 사각 region이다. 같은 texture의 같은 셀·같은 좌표·같은 scale로 다시 그린다. 새 사각 색칠로 원래 손/팔/몸체를 덮거나, 임의의 장갑 이미지를 새로 그리는 명세가 아니다.
- 손 영역은 최대 4×4 원본 픽셀이다. 셀 경계를 넘지 않도록 가장자리 주먹의 region 폭/높이를 제한했다. 투명 픽셀은 원본 투명 상태 그대로 렌더링한다.
- 쉬는 검은 down -55°,up -125°,left -145°,right -35°의 대각 위 방향을 출발안으로 둔다(화면 +x=0°, +y=90°). 손이 발 부근에 있으므로 아래로 긴 검을 향하게 하면 땅을 뚫거나 끌리는 인상이 생길 수 있다.
- 물리적으로 같은 검이 보이도록 일정한 blade 형태/불투명 본체, 짧게 사라지는 trail을 권고한다. 구체적인 길이/폭/active 판정 endpoints는 전투 담당이 코드와 같이 고정·검사한다.

## 원본 팔레트와 어울리는 code-native 무기

검은 외곽선 `#141B1B`, 차분한 금속 면 `#8D977F`, 그림자 `#5F7160`, 좁은 밝은 모서리 `#E3F1F5`, 어두운 손잡이 `#3B3643`, 끝장식 `#4E484A`를 사용하도록 JSON에 제안했다. 모두 조사한 atlas 팔레트에서 고른 색이다. 밝은 흰 막대/사진풍 금속보다 작고 단순한 칼날·손잡이·가드 구분을 우선한다. 이것은 래스터 원화 제작이 아니라 엔진 도형 렌더링 명세다.

## 변경하지 않는 수치 / 필요한 검수

준비50ms,활성85ms,회수140ms,ease3,hitstop65ms,피해15,이동230을 유지한다. 원본 PNG/맵/월드/카메라와 본편은 변경하지 않는다.

그러나 손 pivot은 이전 몸통 중심과 다르다. 특히 오른쪽은 idle→attack 손이 28px 앞으로 이동한다. 따라서 **같은 시간 설정을 유지해도 최초 피해의 거리/방향별 관측 시점은 달라질 수 있다.** 이전 62px 표적의 66.667ms를 그대로 보장하지 않는다. 새 가시 칼날과 같은 endpoints로 판정하고, 벽/근접/8방향/한 번 피해/hitstop/입력 버퍼를 재검사한다. 비교 fixture의 과거 원점까지 새 socket으로 바꿔 구 기준을 오염시키지 않는다.

독립 검토 항목은 원본 손 픽셀/pose 문맥, JSON 변환과 원본 region 경계, idle/contact 네 방향의 실제 화면에서 손잡이 결합·몸체 앞뒤·원래 장갑 가림이다. 가상의 팔 길이·관절 또는 Fin 완성 몸체를 이 자료로 주장하지 않는다.

## 원화 자체의 한계

제작자 읽기 검사는 네 방향×5개행(0/4/1/2/3), 총20pose를 실제로 순회했다. 모든 socket의 해당 원본 픽셀이 붉은/주황 주먹색이고 모든 overlay rectangle이 16×16 셀 내부이며 source SHA가 동일함을 확인했다. 첫 검사 보조 명령은 PowerShell 배열 산술 오류로 0pose였으므로 무효로 취급했고, 오류 즉시 중단 및 정확히20pose 조건을 추가해 다시 확인했다. 이 검사는 Godot 실행/손과 칼의 시각 결합 성공 판정 또는 독립 DA가 아니다.

기존 대역의 down 화면 오른쪽/up 화면 왼쪽으로 뻗은 주먹을 따르면 왼손잡이처럼 읽힐 수 있다. root가 **대역의 실제 원화 손을 사용하는 제한된 범위**를 승인했으며, Fin의 승인된 오른손 검/왼손 방패는 바꾸지 않는다. 원본을 좌우 반전해서 다른 방향/손잡이를 조작하지 않는다. 기존 팔 pose0/4를 바꿔 사용하는 것이므로 부드러운 다프레임 팔 모션을 새로 제작한 것도 아니다. 명세의 독립 검토는 아래 범위로 완료됐고 새 실행/시각 검증은 아직 대기 중이다.

NPC 담당의 독립 명세 DA 필수수정0: 원본64×128 직접 보기와 SHA 확인, idle/attack8socket의 주먹색 실제 픽셀·8개actorLocal 변환, 전체20pose overlay의 셀 경계 및 socket 포함을 확인했다(근거 `283769`, `ce7b91`). 설명 전체의 대역 손잡이/Fin 정본 분리도 검토했다. 실제 손–칼 결합 화면이나 모든 걷기 프레임의 미학을 독립 승인한 것은 아니다. 이 문구는 제작자가 받은 타 담당 검토 결과를 기록한 것이며 자체 DA가 아니다.

JSON의 status는 고정된 원본 명세임을 뜻하는 `source_spec_v1_runtime_validation_recorded_separately`다. 준비 manifest 작성 뒤 QA 상태만 업데이트하려고 JSON을 변경하지 않는다. 후속 독립 검토/실행 결과는 이 문서 또는 별도 QA에 기록하며, 명세 수정이 실제로 필요하면 새 소스 변경과 재준비 대상으로 처리한다.
