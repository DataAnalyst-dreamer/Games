# 핀 FHD 정면 실행 테스트 01

기존 게임과 별개의 Godot 4.4.1 프로젝트다. 세이브/인벤토리/기존 밸런스를 읽거나 변경하지 않는다. 네트워크와 유료 API가 필요하지 않다.

## 실행

저장소 루트에서:

```powershell
./Launch-Fin-Test.ps1
```

이 작업 공간에 받은 Godot를 자동 탐색한다. 다른 PC는 `-GodotPath C:/path/to/Godot.exe`를 전달하거나 Godot에서 이 폴더의 project.godot을 열고 F6/F5로 실행한다. 실행 정책 변경은 하지 않는다. PowerShell 스크립트가 차단되면 Godot에서 직접 프로젝트를 열면 된다.

자동 검사: `./Launch-Fin-Test.ps1 -SelfTest`

## 조작

- WASD/방향키: 이동. 그래픽은 모든 이동 방향에서 정면으로 고정된다. 측면·후면 걷기 완성을 뜻하지 않는다.
- 자동 이동 버튼: 앞뒤 이동 반복. 다시 누르면 수동으로 돌아온다.
- Space/버튼: 모션 프레임 고정. 이동 자체를 일시정지하는 기능은 아니다.
- 마침표: 다음 프레임. R: 위치·프레임·자동 이동 초기화.
- G: 바닥 격자. H: 발밑 충돌 모양. F11: 전체화면. Esc: 종료.

내부 렌더는 FHD 1920×1080이고 기본 창은 1280×720로 축소 표시한다. FHD 디스플레이에서 F11 전체화면으로 원래 픽셀 크기를 확인한다. 고해상도/다른 종횡비 디스플레이와 OS 확대에서는 표시 결과가 달라질 수 있다. 왼쪽은 2배, 오른쪽은 3배 비교다.

## 3분 확인 순서

1. 정지 상태의 얼굴/투구/장비를 살핀다.
2. S로 앞으로 걷고 놓는다. 대기로 즉시 돌아오는지 본다.
3. 자동 이동 또는 한 프레임씩 보기로 8개 프레임을 확인한다. 얼굴 형태가 바뀌는지, 발이 과하게 미끄러지는지 관찰한다.
4. 회색 장애물과 화면 경계에 접근해 발밑 충돌을 확인한다.
5. R로 초기화하고 F11에서 실제 표시 크기를 비교한다.

## 범위/한계

승인된 정면 이미지에서 다리 부위를 분리한 **동작 블로킹 초안**이다. 얼굴/투구 픽셀은 같지만 다리는 완성된 손그림 키프레임이 아니며 팔·망토의 2차 동작도 미완성이다. 기존 걷기 v1을 확대하거나 재사용하지 않았다. 캐릭터 규격 선택은 반영했지만 정면 아트 픽셀 정리가 전부 끝났다고 보고하지 않는다.

후면·측면·공격·스킬·적 AI·드롭·저장은 이 테스트에 없다. 이 프로젝트의 성공을 본 게임 전체 FHD 이관 완료로 해석하지 않는다. 테스트용 장애물과 격자는 최종 배경 디자인이 아니다.

현재 PNG는 사용자가 품질을 거절한 이전 동작 초안을 보존한 **검사 fixture**다. 아래 설정 로더 개선은 그림이나 모션 품질 개선이 아니다. `tools/build_fin_front_test.py`는 역사적 생성 경로이며 새 애셋 제작 방식으로 권장하지 않는다. 출처는 manifest.json 참고.

## 새 시트 연결용 최소 설정

`test_config.json`의 `walk_texture`/`idle_texture`는 PNG 경로다. 프로젝트 안 파일은 `res://` 경로로 지정하고 먼저 Godot에서 가져온다. `cell`은 셀 너비·높이, `frame_count`는 정면 걷기 프레임 수, `foot_anchor`는 셀 안 캐릭터 원점이다. 걷기 PNG는 정확히 `cell 너비 × frame_count` 너비의 단일 행, 대기 PNG는 셀 하나 크기여야 한다. 원점은 지지발의 화면 좌표를 고정한다는 의미가 아니다.

선택 항목 `frame_duration_sec`를 양수로 지정하면 이동 중 각 프레임을 같은 시간 동안 재생한다(FPS = 1 / 값). 생략하면 기존 `pixels_per_frame`만큼 실제 이동할 때 다음 프레임으로 넘어간다. 정지하면 두 방식 모두 대기로 돌아간다. 예전 설정은 기존 경로·8프레임·96×128 셀·[48,112] 원점을 기본값으로 사용한다. 이 셀 기본값은 새로운 디자인 승인을 뜻하지 않는다.

Godot 직접 실행 시 `-- --validate-config-only`로 PNG 경로·크기 및 위 애셋 설정만 검사할 수 있다. `-- --config=별도설정경로 --validate-config-only`도 가능하며 기존 설정을 덮어쓰지 않는다. 성공은 `FIN_CONFIG_RESULT: PASS`/종료 코드 0, 실패는 `FIN_CONFIG_ERROR`/0이 아닌 종료 코드다. 전체 게임 설정·아트 품질 검수 기능은 아니다.

## 시간 기반 재생 실제 검사 — 2026-09-13

`--self-test`는 기존 그림의 앞 4개 아틀라스 영역을 메모리에서 사용해 시간 기반 분기를 실제 physics tick으로 실행한다. 거리당 프레임 값을 크게 두어 거리 모드와 구분하고, 4프레임 wrap·실제 Sprite 텍스처 선택·이동 중 모션 pause·pause 상태 정지·해제 후 idle·재시작을 검사한 뒤 설정/프레임 배열/위치/재생 상태를 복원한다. `test_config.json`과 PNG를 덮어쓰지 않는다. 대체 크기 PNG를 파일에서 불러오는 전체 경로 검증과는 별개다.

실제 headless 실행: 33 PASS, `FIN_TEST_RESULT: PASS`, 종료 0. [로그](../../docs/qa/fin-config-timing-selftest.log). 새 모션 제작·시각 품질 승인·본 게임 적용을 뜻하지 않는다. 최초 기본 user 로그 경로 실행은 로그 접근 실패 후 엔진이 비정상 종료했으며, 프로젝트 내부 `--log-file` 지정으로 재실행했다. 재실행의 시스템 인증서 저장소 경고는 남았지만 테스트는 모두 실행되었다.
